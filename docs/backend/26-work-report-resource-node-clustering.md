# 작업 보고서 — 자원 노드를 군집(클러스터)으로 랜덤 배치

> backend/24에서 만든 "코어 중심 고정 원 위에 균등 배치"를, "코어 주변 무작위 위치에
> 나무숲/채석장처럼 뭉쳐서" 나오도록 바꿨다. 낮에 웨이브를 막고 나서 "저쪽에 채집처가
> 있었지" 하고 기억해서 찾아가는 플레이 경험을 노린 요청이었다.

---

## 1. 기획 — 무엇을, 왜

기존 배치(backend/24)는 나무 10개/돌 6개를 코어 중심 고정 반지름 원 위에 균등하게
뿌렸다 — 웨이브마다 위치가 바뀔 이유가 없다는 이유로 RNG 없이 결정론적으로 뒀었다.
그런데 실제 플레이 감각으로 보면 이 배치는 "코어 주변 어디서든 몇 걸음이면 나무 하나"
식이라 탐색의 의미가 없고, 노드 하나씩 개별적으로 흩어져 있어서 "그 장소"라는 느낌이
안 생긴다. 요청한 방향은: 나무/돌을 각각 몇 군데에 뭉쳐서(군집) 배치하고, 그 군집을
맵 위 무작위 위치에 놓아서 플레이어가 낮 시간에 "예전에 봐둔 그 숲/채석장"으로
찾아가는 행동을 만들도록 하는 것.

## 2. 과정 — 어떻게 했나

### 2.1 배치 알고리즘 — `World.seedResourceClusters()`

자원 타입별로(나무/돌) 클러스터를 몇 개 만들고, 각 클러스터 중심을 코어 기준
`[CLUSTER_MIN_DISTANCE, CLUSTER_MAX_DISTANCE]`(150~900px) 띠 안의 무작위 각도·거리에
찍는다. 그 중심 주변 `CLUSTER_JITTER_RADIUS`(48px) 안에 노드를 하나씩 흩뿌리는데,
이미 놓인 노드와 `MIN_NODE_SPACING`(20px)보다 가까우면 다시 뽑아서(최대 8회 재시도)
완전히 겹치는 걸 막는다. 총 노드 수는 기존과 똑같이 유지했다 —
나무 2클러스터×5개=10개, 돌 2클러스터×3개=6개. 이번 변경은 "어디에 있는지"만 바꾸고
"얼마나 있는지"(밸런스)는 건드리지 않았다.

### 2.2 RNG 주입 — `World`에 `WorldOptions.rng` 추가

기존엔 배치가 결정론적이라 `World`에 RNG 자체가 없었다. 진짜 무작위 배치로 바꾸면서
`WaveManager`와 똑같은 패턴(옵션으로 `rng?: () => number` 받고 기본값 `Math.random`)을
그대로 가져왔다 — 실제 게임에서는 매판 다른 배치가 나오고, 테스트에서는 시드를 박아
결정론적으로 검증할 수 있다.

### 2.3 겪은 문제 — 군집이라 "가장 가까운 노드 하나"를 가정한 테스트가 깨짐

`world-building.test.ts`의 리스폰 테스트가 새로 만든 코드에서 일관되게(우연이 아니라
매번) 실패했다. 원인: 이 테스트는 "플레이어를 노드 위치에 세우고 `harvest()`를
반복 호출해서 그 노드 하나를 고갈시킨다"는 방식이었는데, 노드가 군집으로 배치되면서
반경(harvestRadius=32px) 안에 **같은 타입의 다른 노드가 하나 더 있을 수 있게 됐다**
(클러스터 지터 반경 48px 안에 노드가 여러 개라 이런 겹침이 흔하다). 채집 쿨다운은
`${playerId}:${resourceType}` 단위라 노드별이 아니어서, 첫 번째 노드가 고갈된 뒤에도
쿨다운만 지나면 바로 옆 노드를 대신 캐버렸다 — "고갈 후 채집 시도는 실패해야 한다"는
검증이 실제로는 다른 노드를 캐는 바람에 깨진 것이다.

고친 방법: `harvest()` 반복 호출로 자연스럽게 고갈시키는 대신, 반경 안 모든 노드를
`remainingHarvests = 0`으로 직접 만들어서 "군집 안 다른 노드로 새는" 경로 자체를
차단한 뒤 리스폰 로직만 검증하도록 테스트를 다시 짰다.

또한 고정 좌표(예: `(550,500)`)에 건축하는 테스트들이, 새로 무작위가 된 자원 노드
위치와 극히 낮은 확률로라도 우연히 겹치면 간헐적으로 실패할 수 있다는 걸 이번
세션에서 이미 여러 번 겪은 패턴이라 미리 차단했다 — `world-building.test.ts` 전체가
시드 고정 RNG(`createTestWorld()` 헬퍼)로 `World`를 만들도록 바꿔서, 이 파일의 모든
테스트가 완전히 결정론적인 배치를 쓰게 했다(`world-combat.test.ts`/`wave.test.ts`는
자원 노드를 다루지 않아 그대로 뒀다).

### 2.4 검증

배치 알고리즘을 독립적으로 재실행해서(같은 시드) 실제로 군집이 형성되는지 좌표로
확인했다 — 예를 들어 나무 클러스터 하나가 `(-277,-19) ~ (-303,-10)` 범위(반지름
30px 안)에 5개 다 몰려 있고, 다른 나무 클러스터는 `(199,421) ~ (226,463)`으로 멀리
떨어져 있는 식이다. 돌도 마찬가지로 두 군집이 뚜렷하게 나뉘었다. Playwright로도
스폰 지점 근처(예전엔 항상 노드가 보였던 자리)에 더 이상 노드가 없는 것도 확인했다
(무작위 배치라 코어 바로 옆에 몰릴 이유가 없어졌다는 뜻).

```bash
pnpm --filter @dropfall/shared test     # 122 passed, 8회 연속(시드 고정) 안정
pnpm typecheck                          # client/server 전체 통과
pnpm lint                               # 에러 0
pnpm build                              # client(vite)/server(tsup) 전체 통과
```

전부 통과.

## 3. 결과

- `MIN_NODE_SPACING`/`CLUSTER_JITTER_RADIUS`/`CLUSTER_MIN_DISTANCE`/
  `CLUSTER_MAX_DISTANCE`/클러스터 개수·개당 노드 수는 전부 플레이스홀더다. 실제
  플레이 감각(탐색이 너무 쉬운지/어려운지, 클러스터가 너무 밀집돼 보이는지)을 보고
  조정이 필요할 수 있다.
- 서로 다른 클러스터끼리(예: 나무 클러스터 두 개)는 겹침 검사를 안 한다 — 반경 띠가
  넓고 지터 반경이 작아서(48px) 우연히 겹칠 확률이 낮다고 보고 단순화했다. 실제로
  문제가 되면(예: 두 나무숲이 붙어서 하나처럼 보임) 그때 클러스터 중심 간 최소 거리
  검사를 추가하면 된다.

### 3.1 후속 조정 — 생성 범위를 좁힘

실제로 플레이해보니 `CLUSTER_MAX_DISTANCE`(원래 900px)가 너무 멀어서, 낮 시간 안에
왕복하기 부담스러운 위치에 클러스터가 나오는 경우가 있었다(맵 자체는 코어 기준
최대 1024px까지라 900px도 "맵 안"이긴 했지만, 그게 문제가 아니라 플레이 동선
기준으로 멀었다). 몬스터 스폰 반경(`wavesData.spawnRadius`=300)을 기준으로 삼아
`CLUSTER_MIN_DISTANCE`를 100px, `CLUSTER_MAX_DISTANCE`를 350px로 좁혔다 — 가장 먼
클러스터도 몬스터 스폰 반경을 살짝 벗어나는 정도라, "위험을 살짝 감수하면 닿는
거리"를 목표로 잡았다. 플레이어 이동 속도(100px/s) 기준으로 가장 먼 거리를 왕복해도
7초 안팎이라, 90초 낮 시간에 부담 없이 다녀올 수 있다.

테스트는 이미 시드 고정 `World`를 쓰고 있어서(§2.3) 값만 바꾸고 다시 돌렸다 —
5회 연속 통과 확인. 오히려 범위가 좁아지면서 건축 테스트들의 고정 좌표(예: `(500,500)`,
코어에서 거리 707)가 자원 노드 배치 범위(100~350px)와 절대 겹치지 않게 돼서, 우연한
충돌 가능성이 이전보다도 더 줄었다.

### 3.2 후속 조정 — 최소 거리를 한 번 더 늘림

100px도 플레이어 스폰 반경(40px)에 비하면 여유가 있어 보였지만, "너무 가까우면
너무 쉬워진다"는 우려로 `CLUSTER_MIN_DISTANCE`를 100px → 150px로 한 번 더 올렸다.
`CLUSTER_MAX_DISTANCE`(350px)는 그대로 뒀다 — 이번엔 "가장 가까운 클러스터가 스폰
바로 앞이라 탐색 없이도 쉽게 닿는" 쪽만 문제였고, "너무 멀어서 부담"은 §3.1에서
이미 다뤘다. 시드 고정 테스트로 5회 연속 통과 확인.

## 4. 다음 작업

- 클라이언트(backend/25)의 렌더링/입력 쪽은 노드 위치를 그대로 스냅샷에서 받아
  그리기만 하므로 추가 변경이 필요 없다 — 이미 군집으로 뭉친 채 잘 보인다.
- 클러스터 위치를 클라이언트가 미리 알 방법(예: 미니맵에 발견한 채집처 표시)은
  아직 없다 — "기억해서 찾아간다"는 지금은 순전히 플레이어의 기억에 의존한다.
  나중에 미니맵/마커 시스템이 생기면 발견한 클러스터를 표시하는 기능을 고려할 수
  있다.
