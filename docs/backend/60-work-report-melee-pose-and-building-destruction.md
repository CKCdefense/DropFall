# 60. 근접 자세·건축모드 제거·건축물 파괴 (작업 보고)

근접 무기를 사선으로 들게 하고, 건축모드를 통째로 걷어내고, 설치물을 때려 부술 수
있게 했다.

## 1. 근접 무기를 사선으로 든다

평소 자세가 조준선과 **정확히 일직선**이라 도끼든 방망이든 창처럼 앞으로 뻗고 있었다.
어깨에 걸치듯 40° 위로 젖히면 "휘두르기 직전"으로 읽힌다.

젖히는 각(`MELEE_REST_TILT`)이 곧 **휘두르기의 시작점**이기도 하다. 예전엔 젖히는 정도를
부채꼴 폭에서 따로 계산했는데(`halfArc * 0.6`), 그러면 평소 자세와 시작점이 달라 좌클릭한
순간 무기가 툭 튀었다가 내려온다. 두 값을 하나로 합쳤다.

원거리 무기는 그대로 조준선을 향한다 — 총은 겨눈 곳을 봐야 한다.

**사거리는 자연히 줄었다.** 무기를 위로 든 만큼 앞으로 닿는 거리가 짧아지므로,
근접 사거리 전부에 `cos(40°) ≈ 0.766`을 곱했다(뭉둥이 37 → 28, 돌창 50 → 38, 맨손 18 → 14).
휘두르기 이펙트 크기는 사거리에서 파생되므로 따라서 줄어든다.

## 2. 건축모드 제거

`B` 토글, 좌클릭 설치, 우클릭 취소, 철거 모드, HUD의 모드 표시가 모두 사라졌다.

설치 경로가 **아이템을 들고 놓는 것 하나**로 줄었다. 두 경로가 같은 칸에 같은 규칙으로
짓는데 비용만 달랐던 게(창고 자원 vs 아이템) 오래된 부담이었다 — 이제 아이템 한 개가
곧 비용이다.

같이 정리한 것:

- `World.placeBuilding` / `demolishBuilding`과 그 메시지·프로토콜 타입
- `buildings.json`의 `resourceCost`(건축모드 전용 값이라 쓰는 곳이 없어졌다)
- 커서 미리보기는 남는다 — 이제 **건축 아이템을 들었을 때만** 뜬다

## 3. 설치물을 때려 부순다

주먹이든 무기든 근접 타격이 건축물을 깎는다. 잘못 세운 벽을 치우려고 모드를 켤 이유가
없어졌다.

**해머만 아이템을 돌려준다.** 해머는 짓는 도구라 뜯어서 회수하는 게 자연스럽고, 그 외
무기로 때려 부수면 부서진 것이니 남는 게 없다.

여기서 기존 **수리** 기능과 부딪혔다(§56에서 넣은 것). 해머가 때릴 때마다 고친다면
영원히 못 뜯고, 반대로 늘 부순다면 수리가 사라진다. 그래서 상태로 갈랐다.

| 해머로 때린 대상 | 결과 |
|---|---|
| 체력이 닳은 건축물 | **수리**(자원 소모) |
| 체력이 가득한 건축물 | **철거** — 한 방에 뜯고 아이템 드랍 |

한 방에 뜯는 건 의도다. 여러 번 때려야 하면 첫 타격에 체력이 깎이는 순간 다음 타격이
수리로 읽혀 영원히 못 뜯는다.

건축물 종류 → 아이템 매핑은 `items.json`에서 **거꾸로 만든다**. 손으로 적어 두면 아이템이
늘 때 한쪽만 고쳐져 "해머로 뜯었는데 아무것도 안 나온다"가 된다.

## 4. 검증

- shared 536 + server 31 통과. 건축 테스트 27개가 깨져서 새 규칙으로 고쳤다 —
  설치는 아이템 경로로, 철거 테스트는 "근접 타격으로 부수기"로 다시 썼다(일반 무기는
  사라지고, 해머는 아이템이 떨어지고, 부순 칸에 다시 지을 수 있다).
- 헤드리스 크롬: 방망이가 좌우 어느 쪽을 봐도 **사선 위로** 들리고, 울타리를 방망이로
  때리면 사라지며 바닥에 아무것도 안 남는다.

테스트를 고치다 하나 배웠다 — 시작 지급품이 인벤토리 네 칸을 다 채우고 있어서
`inventory.add()`가 조용히 실패했다. 건축 아이템이 안 들어가니 설치가 통째로 안 됐다.

## 5. 남은 것

- 손상된 건축물은 **해머로 뜯을 수 없다**(먼저 고쳐야 한다). 규칙상 어쩔 수 없지만
  "부서진 벽을 회수하고 싶다"는 요구가 나오면 다시 봐야 한다.
- 사거리를 일괄로 0.766배 했다. 무기별 그림 길이에 맞춰 다시 재는 편이 정확하지만,
  지금은 자세 변화의 기하학적 결과를 그대로 적용했다.
- 건축물 파괴에는 이펙트가 없다(붕괴 FX `fx_collapse`가 아틀라스에 있는데 아직 안 붙였다).
