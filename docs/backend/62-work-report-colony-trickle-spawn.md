# 62. 콜로니 트리클 스폰 — 저장분 소진 후에도 계속 파밍 가능 (작업 보고)

> [08-demo-readiness-review.md](../08-demo-readiness-review.md) 공유 후 받은 게임 흐름 피드백
> 4건 중 #3("아침에 콜로니로 에너지 파밍하려는데 4마리 제한으로 거의 불가능") 처리.
> 순서는 사용자와 상의해 1(공격 스탯)→3(이 작업)→2→4로 정했다.

## 1. 기획 — 무엇을, 왜

콜로니는 "저장분(stored) 소진형" 모델이다. 1단계 저장분이 4마리뿐이라, 아무리 오래
지키고 있어도 하루에 최대 4마리만 잡을 수 있고 그걸로 끝(정화)이었다 — 리스폰 주기
(`guardRespawnSeconds=2.5초`) 자체는 빠른데, 정작 총량이 너무 작아서 "아침 내내 콜로니를
지키며 파밍"이라는 플레이가 성립하지 않았다.

사용자에게 두 가지 방향(A. 지속 스폰 신규 메커니즘, B. 기존 저장량만 늘리는 손쉬운 튜닝)을
제시했고, **A(요청하신 방식 그대로)**로 결정됨.

## 2. 과정 — 어떻게 했나

### 2.1 설계
저장분(stored) 모델은 그대로 두고(정화/성장/밤 침공 기여 등 기존 메타는 안 건드림),
**stored가 0이 된 뒤에도 플레이어가 트리거 반경 안에 있으면** 더 느린 주기
(`guardTrickleSeconds`)로 "여분" 수호대가 계속 나오게 했다. 이 여분은 stored를 깎지
않는다 — 깎을 게 없어서다.

- `packages/shared/src/data/colonies.json`: `guardTrickleSeconds: 6` 추가
  (`guardRespawnSeconds=2.5`보다 커야 "저장분 있을 때보다는 느리게"라는 의도가 성립 —
  zod `.refine()`으로 강제)
- `packages/shared/src/sim/world.ts`의 `tickColonyGuards()`: `stored > 0` 여부로
  타이머 값만 갈아끼운다(`hasStored ? guardRespawnSeconds : guardTrickleSeconds`).
  `guardConcurrent` 동시 상한은 트리클에도 그대로 적용 — 소스와 무관하게 화면에 몰리는
  수는 항상 같다.

### 2.2 정화 판정 순서를 같이 고쳐야 했다
처음 구현하고 보니 기존 정화 판정(`stored<=0 && guardIds.size===0`이면 즉시 정화)이
트리거 여부를 안 보고 있었다 — 마지막 수호대를 잡은 그 틱에 stored도 0, guardIds도
0이라, **트리클 타이머가 돌기도 전에** 콜로니가 정화되어 버렸다(트리클 자체가 발동할
틈이 없음). `triggered` 판정을 정화 체크보다 먼저 계산해서, "저장분·수호대 다 없고
**+ 아무도 트리거 반경에 없을 때만**" 정화하도록 순서를 바꿨다 — 즉 플레이어가 자리를
지키고 있으면 정화가 보류되고 트리클이 대신 돈다. 정화하려면 다 비운 뒤 실제로
자리를 떠야 한다(설계상 자연스러운 "그만 지킨다"는 신호).

### 2.3 기존 테스트가 이 변경으로 깨졌다
`purifyByCombat` 테스트 헬퍼가 "플레이어를 그 자리에 둔 채 계속 죽이면 언젠가
정화된다"고 가정하고 있었는데, 새 규칙에선 **플레이어가 그 자리에 있는 한 정화가
안 되므로** 무한 루프에 빠져 타임아웃(500회 반복 후 에러)했다. 헬퍼를 "다 비우고 →
자리를 떠서 → 정화를 확인" 순서로 고쳤다.

## 3. 결과 — 검증

새 테스트 2개 추가(`colony.test.ts`):
- 저장분 소진 후에도 플레이어가 있으면 `guardTrickleSeconds` 지나 새 수호대가 나오고,
  `stored`는 여전히 0으로 유지되는지
- 트리클 대기 중 플레이어가 트리거 반경을 벗어나면 그 즉시 정화되는지(더 이상 안 나옴)

```
pnpm --filter @dropfall/shared test    # 539 통과 (콜로니 17개 포함)
pnpm --filter @dropfall/server typecheck && test   # 통과, 31개
pnpm --filter @dropfall/client typecheck            # 통과
pnpm lint                                           # 에러 0
```
