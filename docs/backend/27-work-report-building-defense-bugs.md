# 작업 보고서 — 건축물 관련 버그 두 건 수정

> 제보받은 버그 두 개를 고쳤다: (1) 코어를 건축물로 완전히 둘러싸면 몬스터 전체가
> 멈춰버리는 문제, (2) 벽(투사체 차단 설정)인데도 투사체가 그냥 통과하는 문제.
> 첫 번째를 고치다가, 몬스터가 raw 거리만으로 사거리 판정을 통과해서 **벽을 무시하고
> 코어/타겟을 직접 공격해버리는** 더 근본적인 버그를 하나 더 찾아서 같이 고쳤다.

---

## 1. 기획 — 무엇을, 왜

제보받은 버그:
1. 코어 주변을 건축물로 모두 감싸면 모든 몬스터가 멈춰버린다.
2. 울타리는 투사체를 통과시키고 벽은 막아야 하는데, 벽도 투사체가 그냥 통과한다.

버그 2는 사실 docs/backend/24의 "다음 작업"에 이미 알려진 미구현 항목으로 적어뒀던
것이다("`blocksProjectile` 데이터 필드는 있지만 `resolveProjectileHits()`가 건축물을
아직 검사하지 않는다") — 이번에 실제로 구현했다.

## 2. 과정 — 어떻게 했나

### 2.1 버그 1 — 몬스터 정지, 그리고 그 아래 숨어있던 진짜 버그

**1차 원인**: 코어를 완전히 둘러싸면 Dijkstra가 코어 셀 자체(cost=0) 말고는 아무 데도
도달을 못 한다 — `FlowField.sampleDirection()`이 몬스터 위치 기준 계속 `{0,0}`을
돌려준다. `tickMonsters()`는 이 값을 그대로 이동 방향으로 썼기 때문에, 몬스터가
그 자리에서 영원히 정지했다.

**1차 수정**: `sampleDirection()`이 `{0,0}`(경로 없음)을 돌려주면, backend/21에서 만든
"장애물 없을 때 코어로 직진" 로직과 같은 폴백을 쓰도록 했다 — 우회로가 없어도 코어를
향해 계속 직진시켜서, 결국 가로막은 건축물에 부딪히면 공격을 시작하게 한다.

**여기서 발견한 2차 버그**: 1차 수정 후 실제로 테스트해보니, 몬스터가 벽 쪽으로
다가가긴 하는데 벽 바로 앞에서 멈춰서 **벽이 아니라 코어를 공격**하고 있었다(코어
HP가 실제로 깎임 — 1000 → 870, 20초 동안). 원인을 추적해보니 `tickMonsters()`의
우선순위가 "타겟/코어가 사거리 안이면 무조건 그것부터 공격, 막는 건축물 검사는
사거리 밖일 때만"이었다 — `distanceToCore <= attackRange + CORE_RADIUS`가 **벽이
있든 없든 그냥 직선 거리만** 재는 조건이라서, 벽을 사이에 두고도 raw 거리만
가까우면 그냥 통과해서 공격해버린 것이다. 벽으로 코어를 감싸도 몬스터가 코앞까지
와서 벽 너머로 코어를 때릴 수 있었다는 뜻 — 방어 건축물이 사실상 무의미해지는
심각한 버그였다. 같은 구조가 추격 타겟(플레이어) 쪽에도 있어서, 플레이어가 벽으로
자기 주변을 두르고 있어도 몬스터가 raw 거리로 사거리에 들어오면 벽을 무시하고
플레이어를 직접 때릴 수 있는 상태였다.

**2차 수정**: 우선순위를 뒤집었다 — **막는 건축물 검사를 항상 먼저** 하고, 막는
게 없을 때만 타겟/코어를 공격한다. 두 분기(추격 타겟 분기, 코어 분기) 모두 동일하게
고쳤다.

### 2.2 버그 2 — 투사체가 벽을 통과

`resolveProjectileHits()`가 몬스터 충돌만 검사하고 건축물은 아예 안 봤다. 몬스터
판정에서 안 맞았으면 건축물 판정으로 넘어가서, `blocksProjectile`이 `true`인
건축물(벽)과 겹치면 투사체를 소멸시키도록 추가했다. 울타리(`blocksProjectile: false`)는
검사 대상에서 아예 제외해서 그대로 통과한다. 건축물 자체는 데미지를 입지 않는다 —
몬스터 공격으로만 부서지는 기존 규칙 그대로다.

## 3. 결과 — 검증

새 테스트 3개 추가(`world-building.test.ts`):
- 코어를 8방향 벽으로 완전히 둘러싸도 몬스터가 멈추지 않고 결국 벽을 공격하는지,
  그리고 **벽이 멀쩡한 동안 코어 HP가 전혀 깎이지 않는지**(2차 버그의 회귀 테스트)
- 벽은 투사체를 막고 통과시키지 않는지
- 울타리는 투사체를 막지 않고 통과시키는지

```bash
pnpm --filter @dropfall/shared test     # 125 passed (기존 122 + 신규 3), 8회 연속 안정
pnpm typecheck                          # client/server 전체 통과
pnpm lint                               # 에러 0
pnpm build                              # client(vite)/server(tsup) 전체 통과
```

전부 통과.
