# 작업 보고서 — 코어 북쪽 사각지대 반투명 처리 + 피격 알림 연출

> 코어 스프라이트가 충돌 판정보다 훨씬 위(북쪽)까지 그려지는 구조라, 그
> 사각지대에서 공격하는 몬스터가 코어 그림에 완전히 가려 안 보였다("12시
> 방향 공격이 안 보인다"는 제보). 그 구역이 비지 않으면 코어를 반투명하게
> 만들고, 코어가 맞을 때마다 월드/HUD 양쪽에서 알림 연출을 넣었다.

---

## 1. 기획 — 무엇을, 왜

원문 요청: "추가로 코어에 씌워진 에셋에 가려져서 유닛이 12시방향으로
들어와서 코어를 때리는게 보이지않거든? 이부분은 어떻게 고치는게 좋을까
그리고 코어 공격당하고있다는 알림효과도 있어야될거같아"

## 2. 과정 — 어떻게 했나

### 2.1 원인 — 앵커와 그림의 크기 차이

코어 스프라이트 앵커(`CORE_ORIGIN_Y=0.68`, 받침대 시각적 중심)는 8각
발자국(coreShape.ts) 충돌 경계(y≈-27)보다 훨씬 위(y≈-73)까지 그림을
그린다. 그 사이 — 발자국 밖이라 몬스터가 설 수 있지만 그림에는 가려지는
구간 — 에서 공격하면 몬스터가 코어 그림에 완전히 가려졌다. 앵커 값 자체는
"건축 구역·광원과 코어가 원점 대칭이어야 한다"는 다른 이유로 의도적으로
고른 값이라(코드 주석 확인) 건드리지 않고, 렌더링 쪽에서 대응했다.

### 2.2 반투명 처리 — `EntityRenderer.updateCoreBlindZone`

사각지대(x:±55, y:-80~-20 — 발자국/그림 경계보다 살짝 넉넉하게)에 몬스터가
있으면 코어 몸체 알파를 0.4로 낮춘다. 상태가 실제로 바뀔 때만(비어있다↔
있다) 트윈을 새로 걸어서, 매 스냅샷마다 다시 걸어 깜빡이는 일이 없게 했다.

### 2.3 피격 알림 — 월드 + HUD 이중화

- `EntityRenderer.playCoreHit()`: 코어 체력이 줄면(플레이어/몬스터 피격과
  같은 추론 — 스냅샷에 타격 이벤트가 따로 없다) 몸체를 흰색으로 한 번
  플래시하고, 그보다 오래 남는 붉은 테두리 펄스 링을 코어 주변에 띄운다.
- `HudScene.flashCorePanel()`: 좌상단 코어 HP 패널 테두리도 같이 붉게
  펄스한다 — 카메라가 코어에서 멀리 있거나 몬스터에 가려도 이 HUD 패널은
  항상 화면에 있어서 "지금 맞고 있다"를 놓칠 수 없다.

## 3. 결과 — 검증

Playwright로 로컬 dev 서버에 접속해 dev 콘솔의 `spawn`/`corehp` 커맨드로
몬스터를 코어 북쪽에 스폰시키고 코어 체력을 깎아, 세 효과(반투명, 링 펄스,
HUD 테두리 펄스)가 실제 화면에서 동시에 동작하는 것을 스크린샷으로 확인했다
— 반투명해진 코어 그림 사이로 몬스터가 실제로 비쳐 보였다.

```bash
pnpm --filter @dropfall/shared test   # 430/430
pnpm --filter @dropfall/client typecheck
pnpm lint
```
