# 작업 보고서 — 전원 다운 즉시패배 + 낮 스킵 투표 구현

> [backend/11](11-mvp-scope-proposal-combat-wave.md)에서 팀 협의로 남겨뒀던 마지막 두
> 항목을 팀이 확정("적용하기로 했다")해서 구현했다. 낮 스킵 투표는 **전원 만장일치** 방식으로
> 확정했다.

---

## 1. 기획 — 무엇을, 왜

[backend/15](15-work-report-combat-monster-wave.md)에서 전투·몬스터·웨이브 MVP를 구현할 때
의도적으로 뺐던 두 항목이다.

- **전원 다운 = 즉시 패배**: 플레이어 전원의 HP가 0이 되면 그 즉시 게임을 패배로 끝낸다.
- **낮 스킵 투표**: 낮 페이즈(90초 고정 카운트다운)를 접속 중인 플레이어 전원이 동의하면
  즉시 끝내고 다음 웨이브로 넘어간다.

투표 방식은 만장일치와 과반 두 가지를 제안받아 **만장일치**로 확정했다 — 협동 게임에서
한 명이 일방적으로 스킵을 강요하지 못하게 막는다는 근거다.

두 기능을 구현하려면 "다운"이 무슨 상태인지부터 명확히 해야 했다. HP 0인 플레이어를 그냥
방치하면(부활 수단 없음) 한 번 다운된 플레이어는 게임이 끝날 때까지 영원히 전투 불능
상태로 남는데, 이는 [backend/11](11-mvp-scope-proposal-combat-wave.md) §2에서 이미
"각 웨이브 종료 시 자동 부활"로 확정해둔 것과 어긋난다. 그래서 이번 작업에 그 부활 로직도
함께 넣었다 — 다운 상태에 복귀 수단이 있어야 "즉시 패배" 조건이 실제로 의미가 있다.

## 2. 과정 — 어떻게 했나

### 2.1 `shared/sim/wave.ts`

`WaveManager.skipDay()` 추가 — `phase === 'day'`일 때만 `beginNextWave()`를 즉시 호출한다.
투표 집계 자체는 World가 맡고, WaveManager는 "스킵해도 된다"는 결정만 받는 얇은 인터페이스로
남겼다.

### 2.2 `shared/sim/world.ts`

- **다운/부활**: `tick()`에서 `waveManager.tick()` 호출 전후로 phase를 비교해
  `night → day`(웨이브 클리어) 전환을 감지하면 `revivePlayers()`(전원 HP를
  `wavesData.playerHp`로 리셋)와 스킵 투표 초기화를 함께 수행한다.
- **즉시 패배**: `checkAllPlayersDown()`을 매 틱 끝에서 호출 — 플레이어가 1명 이상 있고
  전원 `hp <= 0`이면 `waveManager.markDefeat()`. 플레이어가 아무도 없으면(전원 퇴장)
  패배 조건이 아니다.
- **다운 플레이어는 어그로 대상 제외**: `findNearestPlayer()`에서 `hp <= 0`인 플레이어를
  걸러낸다 — 이미 죽은 목표를 계속 때리는 건 의미가 없고, 돌진형/보스가 다른 살아있는
  플레이어나 코어로 관심을 돌려야 한다.
- **스킵 투표**: `castSkipVote(playerId)` — `day` 페이즈가 아니거나 존재하지 않는
  플레이어면 무시. `skipVotes: Set<string>`에 추가하고, 크기가 `players.size`(접속 전원)에
  도달하면 `waveManager.skipDay()`를 호출하고 투표를 비운다. `removePlayer()`에서도
  퇴장한 플레이어의 표를 지운다 — 안 지우면 표를 던지고 나간 사람 수만큼 필요 정족수가
  실제보다 낮게 계산되는 버그가 생긴다.

### 2.3 프로토콜 + 서버 연동

- `skipVote` 메시지는 페이로드가 없다(누가 보냈는지는 `client.sessionId`로 이미 알 수
  있어서) — 별도 메시지 타입 정의 없이 `GameRoom.messages.skipVote: (client) => {...}`로
  바로 처리했다.
- `GameRoomState`에 `skipVoteCount` 추가, `GameRoom.update()`에서 매 틱 동기화.
  필요 정족수(`players.size`)는 이미 상태에 있는 값이라 별도 필드를 안 만들었다.

### 2.4 테스트

`wave.test.ts`에 `skipDay()` 관련 2개 추가. `world-combat.test.ts`에 6개 추가 — 전원
다운 시 패배, 일부만 다운은 패배 아님, 플레이어 0명이면 패배 아님, 다운된 플레이어는
추격 대상에서 제외(코어가 대신 공격받는지로 검증), 웨이브 클리어 시 부활, 스킵 투표
만장일치·중간 상태·유령 플레이어·퇴장 시 표 소멸까지.

**겪은 문제**
- "웨이브 클리어 시 부활" 테스트를 플레이어 1명으로 짰다가 실패했다 — 그 1명이 다운
  상태이므로 "전원 다운"이 되어 웨이브가 끝나기도 전에 즉시 패배로 끝나버렸다(구현이
  아니라 테스트가 틀렸다 — 실제로 solo 플레이어가 다운되면 즉시 패배가 맞는 동작이다).
  플레이어를 2명으로 늘리고 1명만 다운시키는 걸로 고쳤다.
- "다운된 플레이어는 추격 대상 제외" 테스트에서 처음엔 "다운된 플레이어의 HP가 그대로인지"로
  검증했는데, 이미 HP가 0이라 공격을 받든 안 받든 `Math.max(0, ...)`로 클램프되어 항상
  0이라 테스트가 의미 없었다. 대신 "제외됐다면 몬스터가 코어를 공격했을 것"이라는 점을
  이용해 코어 HP 감소 여부로 검증하도록 바꿨다.
