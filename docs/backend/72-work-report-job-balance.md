# 72. 직업 밸런싱 (작업 보고)

직업이 이름과 기초 스탯뿐이던 것을 **고유 능력 + 전용 시작 장비**까지 갖게 했다.

## 1. 능력은 데이터가 들고 있다

`jobs.json`에 배수를 적고, World는 그 값을 곱하기만 한다. 전부 **기본값이 "없음"**이라
값을 안 적은 직업은 아무 효과도 안 받는다 — 능력이 늘어도 다른 직업 데이터를 건드릴
필요가 없다.

| 직업 | 체력 | 스태미나 | 고유 능력 |
|---|---|---|---|
| 병사 | 150 | 100 | 경험치 ×1.2 |
| 의무병 | 125 | 100 | 붕대 제작(전용 레시피) |
| 엔지니어 | 125 | 80 | 수리 자원 ×0.5 |
| 탐색꾼 | 70 | 125 | 이동속도 ×1.1 |

정한 것들:

- **경험치 배수는 받는 쪽에 곱한다.** 처치 경험치는 살아 있는 전원에게 같은 양이
  들어가는데(levels.json), 병사만 제 몫을 더 챙긴다 — 남의 몫을 뺏지 않는다.
- **이동속도는 걷는 속도 자체**를 올린다. 달리기 배수와 곱해지므로 달릴 때도 앞선다.
- **수리비 절반은 올림이다.** 자원이 정수이기도 하고, 비용 2짜리 울타리가 0이 되면
  수리가 공짜가 되어 방벽을 유지할 이유 자체가 사라진다 — 싸지는 것과 공짜는 다르다.
- **의무병 능력은 레시피 쪽에 적었다**(`requiresJob`). 능력이 늘 때마다 World에 분기를
  하나씩 심는 대신, 데이터가 조건을 들고 있게 했다.

## 2. 스태미나 — 100이면 2.5초

초당 소모를 20 → **40**으로 올렸다. 100이면 2.5초, 엔지니어(80)는 2초, 탐색꾼(125)은
약 3.1초를 달린다. 예전엔 100으로 5초를 달려서 사실상 상시 달리기였다.

## 3. 시작 장비는 칸까지 정한다

`loadout.json`의 `byJob`이 그 직업의 퀵슬롯 4칸을 통째로 정한다.

| 직업 | 1번칸 | 2번칸 | 3번칸 | 4번칸 |
|---|---|---|---|---|
| 병사 | 리볼버 | | | 붕대 1 |
| 엔지니어 | T2 해머 | | | 붕대 1 |
| 의무병 | | 붕대 ×인원수 | 알약 2 | AID 1 |
| 탐색꾼 | 토마호크 | | | 진통제 1 |

- **칸 번호를 데이터에 적는다.** "1번칸에 무기"가 곧 조작 습관이라, 순서대로 채우면
  직업마다 무기 칸이 달라진다.
- **지급은 4칸을 통째로 다시 쓴다.** 대기실에서 직업을 바꿔 고르면 앞 직업의 무기가
  남으면 안 되고, 두 번 불려도 결과가 같아야 한다.
- **의무병 붕대는 인원수만큼**이라, 인원이 확정되는 시점(`startColonies`)에 한 번 더
  지급한다. 대기실에서 고른 순간의 인원은 아직 최종이 아니다.

## 4. 토마호크 — 채집 겸용, 전투는 약하게

탐색꾼이 도구 두 개를 들고 다니지 않아도 되게 **나무와 돌을 둘 다 캔다**. 대신 전투력을
40 → **14**로 낮췄다(잡몹 2방).

`toolFamily`를 배열로 바꾸지 않고 `toolFamilies`를 따로 뒀다. 그 값은 채집 말고도
쓰이기 때문이다 — 해머 판정(수리·철거)은 "이 무기가 해머인가" 하나만 묻는데, 배열이
되면 그쪽 질문이 애매해진다. **채집만** 여러 계열을 허용한다.

채집 배수는 2배(`gatherMultiplier`)로, 한 대에 28이다. 나무 54·돌 42라 **둘 다 두 번**에
캔다 — 한 번에 캐지지 않으면서 도끼(18)보다는 확실히 빠르다.

## 5. 직업 전용 레시피는 목록에서 아예 뺀다

코어 티어 잠금처럼 "잠김"으로 보여주지 않는다. 티어는 올리면 열리는 목표지만 직업은
게임 안에서 바꿀 수 없다 — 영영 못 누르는 칸을 띄워 두면 격자만 어지럽고 "왜 안 되지"만
남는다.

## 6. 검증

- 신규 15개(`tests/jobs.test.ts`) — 스태미나 2.5초, 경험치 배수, 이동속도 배수,
  수리비 절반(올림), 직업 전용 레시피(의무병만), 직업별 지급 칸, 인원수 붕대,
  직업 변경 시 앞 지급품 제거, 토마호크 나무·돌 2방 / 잡몹 2~3방
- shared 581 + server 35 통과. 기존 5개는 지급 붕대가 1번칸 → 4번칸으로 옮겨진 것에
  맞춰 고쳤다(테스트가 "0번칸에 붕대"를 전제하고 있었다)

## 7. 남은 것 · 지켜볼 것

- **공격력(attack) 스탯은 손대지 않았다** — 요청에 없어서 현행 유지다
  (병사 8 / 엔지니어 4 / 탐색꾼 3 / 의무병 2).
- **의무병은 1번칸이 비어 시작한다**(맨손). 요청 목록에 2·3·4번칸만 있었다.
- **병사만 원거리 무기로 시작한다.** 리볼버는 rare 등급에 관통 2라 시작 장비치고 강하다 —
  밤에 병사만 안전하게 딜하는 그림이 되는지 봐야 한다.
- **토마호크는 이제 초기 도끼·곡괭이보다 채집이 빠르다.** 탐색꾼 전용이면 의도대로지만,
  드랍/상점으로 남이 얻으면 도구 두 개를 드는 이유가 사라진다.
- **탐색꾼 70 체력**은 기준(100)보다 30% 낮다. 잡몹 피해가 5~7이라 즉사할 정도는 아니지만
  보스 한 방이 26~40이라 **2~3방**이다.

# 부록. 보스 체력 인원수 스케일링

보스는 웨이브마다 **한 마리**라 잡몹처럼 마릿수(`scaledSpawnCount`)로 늘릴 수가 없다 —
체력이 그 자리를 대신한다.

배수 = `base + perPlayer × 인원` (`waves.json`의 `bossHpScaling`, 0.6 + 0.4n).

| 인원 | 배수 | 데몬 | 나이트 | 골렘 | 흑기사 |
|---|---|---|---|---|---|
| 1 | 1.0 | 400 | 550 | 750 | 900 |
| 2 | 1.4 | 560 | 770 | 1050 | 1260 |
| 3 | 1.8 | 720 | 990 | 1350 | 1620 |
| 4 | 2.2 | 880 | 1210 | 1650 | 1980 |

**일부러 선형보다 낮게 잡았다.** 인원이 늘면 화력은 대략 인원수만큼 붙는데(4인이면 4배)
체력은 2.2배만 올린다.

- 선형(4인 4배)으로 맞추면 싸움 길이는 혼자일 때와 같은데 피해야 할 패턴만 늘어난다 —
  "여럿이 잡는 보람"이 사라진다.
- 안 올리면 4인 파티에서 보스가 예고만 하다 녹는다.

자원 노드 배치(`scaledResourceTarget` = 0.6 + 0.4n)와 **같은 모양의 식**이다. 인원
스케일링의 감각을 게임 전체에서 통일해 두면 다음 값도 여기서 시작할 수 있다.

## 스폰 시점에 고정한다

체력은 **보스가 나오는 순간의 인원수**로 정해지고 그 뒤로는 안 바뀐다. 매 틱 다시
계산하면 한 명이 접속을 끊는 순간 싸우는 도중에 상대 체력 바가 저 혼자 움직인다.

## 검증

신규 5개 — 혼자면 데이터 그대로, 인원이 늘수록 증가, 4인 배수가 1보다 크고 4보다 작음,
잡몹 체력은 인원과 무관(잡몹은 마릿수로 는다), 스폰 뒤 인원이 바뀌어도 그대로.
shared 586 + server 35 통과.

## 남은 것

- **보스 공격력·패턴 속도는 그대로다.** 인원이 늘어도 한 사람이 맞는 세기는 같다 —
  요청 범위가 체력이라 손대지 않았다.
- 잡몹 스케일링(`playerScaling` = 2 × (0.6 + 2n))은 **훨씬 가파르다**(1인 5.2배,
  4인 17.2배). 두 값의 감각이 많이 다른데, 잡몹은 "밀려오는 파도"라 마릿수가 곧 압박이고
  보스는 "한 덩어리"라 체력이 곧 시간이라서다. 그래도 나란히 볼 값이다.
