# 74. 낱개 나누기 (작업 보고)

여러 개 든 칸을 나눠 옮길 수 있게 했다 — **Ctrl+드래그 = 절반**.

## 1. 왜 절반인가

수량 입력창(모달·슬라이더)도 후보였지만 이 게임의 스택은 20~100이고, 실사용은 "붕대
5개 중 2개만 창고에" 수준이다. 절반 쪼개기를 두 번 하면 어떤 수량이든 근사하게 나오고,
그 정밀도면 충분하다 — 4칸 인벤토리에 창을 하나 더 여는 건 과하다.

수식키도 이미 문법이 있다. **Shift = 빨리 통째로, Ctrl = 나눠서** — 나란히 서니 배울
게 하나뿐이다.

**올림 절반**이다(5개 → 3개). 홀수에서 내림하면 1개를 나눌 때 0개가 되어 아무 일도
일어나지 않는다 — 손은 움직였는데 결과가 없는 게 제일 나쁘다. 한 개짜리(무기·도구)는
Ctrl을 눌러도 통째로 간다.

## 2. 프로토콜 — 필드 하나

`MoveItemMessage`에 `count?: number`. 없으면 예전처럼 칸을 통째로 옮긴다.

값이 있어도 **서버가 1..보유량으로 조인다.** 클라이언트가 개수를 주장할 수 있으면 한
개를 백 개로 부풀리는 길이 열린다 — 무기를 주장할 수 없게 만든 것과 같은 이유다.

## 3. 나눠 옮기기는 자리를 가린다

`Inventory.takeAt(index, count?)`가 부분만 떼고 나머지를 칸에 남긴다. `placeAt`은 이미
개수 기반이라(같은 물건이면 합치고 초과분을 돌려준다) 손대지 않았다.

문제는 **자리 바꾸기**였다. 다른 물건 위에 나눠 놓으면 `placeAt`이 스왑을 하는데, 원래
칸에는 나머지가 남아 있어서 밀려난 물건을 되돌릴 자리가 없다 — 둘 중 하나가 조용히
사라진다.

그래서 규칙을 하나 세웠다: **나눠 옮기기는 빈 칸이나 같은 물건 위에만** 놓을 수 있다.
통째로 옮기는 이동은 예전처럼 스왑한다.

판단을 **옮기기 전에** 하려고 `SlotAccess`에 `peekAt`을 더했다. 일단 꺼낸 뒤 되돌리는
방식은 애초에 되돌릴 자리가 없어서 성립하지 않는다. 창고·인벤토리는 `slotAt`이 이미
같은 일을 해서 한 겹만 얹었고, 제작·충전 칸 어댑터도 같이 구현했다.

충전 칸에서 **일부만** 꺼내면 타던 진행분은 그대로 둔다 — 남은 재료가 계속 타는 중이다
(통째로 꺼낼 때만 0으로 되돌린다).

## 4. 화면

- 집는 순간의 Ctrl 상태를 **기억한다.** 놓는 순간에 다시 읽으면 끌고 오는 도중에 키를
  뗐다 눌렀다 한 것까지 반영되어 "반만 집었는데 다 옮겨졌다"가 된다.
- 고스트에 개수를 붙인다. **통째로 집으면 안 띄운다** — 칸에 이미 같은 숫자가 적혀
  있어서, 늘 띄우면 무엇이 달라졌는지가 오히려 안 보인다.

여기서 한 번 틀렸다. `endDrag()`가 상태를 지운 **뒤에** `this.splitting`을 읽고 있어서
개수가 늘 `undefined`였다 — 고스트에는 3이 떠 있는데 5개가 통째로 옮겨졌다. 놓는 순간
가장 먼저 지역 변수로 붙잡아 두는 것으로 고쳤다(`source`를 그렇게 다루고 있었는데 새 값만
빠뜨렸다).

## 5. 가이드

조작표에 `CTRL + 드래그 = 절반 나누기 / 여러 개 든 칸만` 한 줄을 넣었다.

넣고 보니 **두 번째 키캡이 설명 글자를 덮고 있었다.** 글자 시작 위치가 고정 칸
(`KEYS_COLUMN`)이라, `SHIFT+클릭`처럼 넓은 키캡 두 장이 오면 그 칸을 넘어간다 — 기존
줄부터 이미 그랬다. 키캡이 실제로 끝난 x와 고정 칸 중 **오른쪽에서** 글을 시작하게 고쳤다
(각주의 줄바꿈 폭도 같이 줄어든다).

## 6. 검증

- 신규 11개(`tests/item-split.test.ts`) — takeAt 부분/전체/초과, 빈 칸 분할, 같은 물건
  합치기, 다른 물건 거부, 통째 이동의 스왑 유지, 개수 부풀리기 차단, 0·음수 하한,
  창고 분할, 총량 보존
- 헤드리스 크롬: 붕대 5개를 Ctrl+드래그 → 고스트에 3 표시 → 3/2로 나뉨. 가이드에 새 줄이
  겹침 없이 표시

## 7. 남은 것

- **1개씩 떼는 조작이 없다.** 절반을 반복해 근사하는 방식이라, 자주 아쉬우면
  `Ctrl+우클릭 = 1개`를 창 안에서만 추가하는 게 자연스럽다 — 프로토콜(`count`)은 이미
  그대로 쓸 수 있어 서버는 안 바뀐다.
- 퀵무브(Shift+클릭)에는 분할이 없다. 통째로 보내는 조작이라는 성격이 분명해 그대로 뒀다.
- 나눠 옮기기가 **거절될 때**(다른 물건 위) 화면에 표시가 없다. 충전 칸의 붉은 테두리
  깜빡임과 같은 신호를 붙일 수 있다.
