# 작업 보고서 — 근접한 몬스터를 원거리 무기로 못 맞히는 버그 + 몬스터 충돌 디버그 테두리

> backend/31에서 몬스터 히트박스를 고친 뒤 "히트박스 버그가 아직 있다"와 "돌진형
> 몬스터가 붙으면 공격 자체가 안 먹힌다"는 제보를 받았다. 재현해보니 진짜 원인은
> 히트박스가 아니라 **원거리 무기의 총구 위치 보정**이었다 — 디버그 테스트로 직접
> 증명하고 고쳤다. 겸사겸사 몬스터에도 플레이어/건축물과 같은 충돌 디버그 테두리를
> 붙여서, 앞으로 비슷한 제보가 오면 코드를 안 읽어도 눈으로 바로 확인할 수 있게 했다.

---

## 1. 기획 — 무엇을, 왜

"몬스터 히트박스가 아직도 이상하다"와 "돌진형(rusher) 몬스터가 붙으면 피격 자체가
불가능하다"는 제보를 받았다. backend/31에서 이미 시각 크기-판정 반경 불일치는
고쳤던 터라, 뭔가 다른 원인이 남아있다고 보고 재현부터 했다.

## 2. 과정 — 어떻게 했나

### 2.1 재현 — `_debug.test.ts`로 직접 증명

플레이어 바로 옆(8px)에 rusher를 두고 기본 무기(권총)로 쏘는 상황을 그대로
재현했다:

```
projectiles [ { x: 19, y: 0, vx: 420, ... } ]
monster hp after 1 shot 20 / 20   ← 전혀 안 맞았다
```

투사체가 `x=19`에서 생겨났는데 몬스터는 `x=8`에 있었다 — **투사체가 생성되는
순간 이미 몬스터를 지나쳐 있었다.** 원인은 `pistol.muzzleOffset=19` — 총알이
플레이어 좌표가 아니라 조준 방향으로 19px 떨어진 "총구" 위치에서 생겨나는
연출 보정(다른 작업자가 무기 이펙트 작업에서 추가) 때문이었다. 총구가 생겨나기도
전에 이미 그 자리를 막고 있는 몬스터가 있으면, 투사체 판정은 그 몬스터를
전혀 모른 채 이미 지나친 지점에서 시작해 버린다 — 아무리 정확히 조준해도
영원히 못 맞히는 구조적 사각지대였다. rusher의 공격 사거리(20px)가 하필
`muzzleOffset`(19px)과 거의 같아서, 근접전 몬스터가 정상적으로 다가와 붙기만
해도 이 사각지대에 자주 걸렸다.

이건 backend/31에서 고친 "히트박스 크기 불일치"와는 완전히 다른 버그였다 —
그래서 "히트박스 버그가 아직 있다"는 제보가 정확했던 것도, 실제로는 별개의
새 버그를 가리키고 있었던 것도 둘 다 맞았다.

### 2.2 수정 — 총구 간격(gap) 판정 추가

`World.fireWeapon()`에서 투사체를 큐에 넣기 전에, **플레이어 좌표 → 총구 좌표
구간(0~muzzleOffset)에 몬스터가 걸쳐 있었는지** 먼저 검사하는
`resolveMuzzleGapHit()`을 추가했다. 원-원 판정이 아니라 원-**선분** 판정이
필요했다 — 몬스터가 정확히 구간 중간에 있으면 양 끝점(플레이어 좌표/총구 좌표)
중 어느 쪽 원과도 안 겹칠 수 있어서, 몬스터 중심에서 그 구간까지의 최단 거리를
직접 구해야 새는 경우가 없다. 걸쳐 있었으면 그 몬스터에게 즉시 데미지를 주고
투사체 자체를 만들지 않는다("총구에서 발사되어 날아가는" 연출이 성립하지 않는
거리이므로 투사체 없이 즉발 처리가 더 정직하다). 근접무기(club/axe/pickax)는애초에
`muzzleOffset` 개념이 없어서(원점 = 플레이어 좌표 그대로) 이 버그와 무관했다.

### 2.3 몬스터 충돌 디버그 테두리 추가

backend/29에서 플레이어/건축물에 붙인 것과 같은 패턴을 몬스터에도 적용했다.
몸통 사각형 크기가 이미 `hitRadius*2`로 맞춰져 있긴 하지만(backend/31), 실제
판정은 **사각형이 아니라 원**이라 네 귀퉁이는 그림만 있고 실제로는 안 맞는
영역이다 — "네모 끝을 스쳤는데 왜 안 맞지"라는 다음 제보가 오기 전에, C 키를
누르면 몬스터 위에도 실제 피격 판정 원(빨간색, 플레이어=하늘색/건축물=노란색과
구분)이 겹쳐 보이도록 미리 붙여 뒀다.

## 3. 결과 — 검증

```bash
pnpm --filter @dropfall/shared test     # 180 passed(기존 178 + 신규 2), 3회 연속 안정
pnpm typecheck                          # client/server 전체 통과
pnpm lint                               # 에러 0
pnpm build                              # client(vite)/server(tsup) 전체 통과
```

`world-combat.test.ts`에 회귀 테스트 2개 추가:
- 총구 간격 안(8px)의 몬스터는 투사체 없이 즉시 명중한다.
- 총구 간격 밖(40px)의 몬스터는 평소처럼 투사체가 날아가 맞힌다(이번 수정이
  일반적인 원거리 사격을 막지 않는지 확인하는 안전장치).

디버그 스크립트로 수정 전/후 정확히 대조했다: 수정 전엔 `monster hp after 1
shot: 20/20`(전혀 안 맞음), 수정 후엔 `projectiles: []`, `monster hp: 8/20`
(투사체 없이 즉시 12데미지 적용)로 확인했다.

## 4. 다음 작업

- 몬스터 충돌 디버그 원은 매 스폰마다 새로 만들어지므로 비용은 무시할 만하지만,
  아직 실제 화면에서 아주 작은 몬스터(trash/rusher, hitRadius=5)의 경우 원과
  사각형 차이가 육안으로는 잘 안 보일 수 있다 — 실제 스프라이트가 들어오고
  나면 이 반경 자체를 다시 조정할 때 이 디버그 테두리로 확인하면 된다.
- 같은 "총구 간격" 사각지대는 이론상 앞으로 `muzzleOffset`이 있는 원거리
  무기가 늘어나도 자동으로 커버된다(무기별 값이 아니라 `resolveMuzzleGapHit`이
  매 발사마다 실제 투사체 생성 좌표를 기준으로 계산하기 때문).
