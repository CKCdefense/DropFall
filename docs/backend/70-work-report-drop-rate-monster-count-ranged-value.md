# 70. 작업 보고서 — 부품 드랍률 조정, 몬스터 수 하향, 원거리 무기 가성비 2차 조정

## 기획

사용자 피드백 7개 중 백엔드(역할 A) 소관인 항목을 정리했다:

- **1, 3, 4번**은 클라이언트(키 리바인드, 퀵슬롯 좌클릭 장착, HUD 개편) 영역 —
  3번은 서버에 `selectSlot()`이 이미 있어 클라이언트가 그 메시지에 좌클릭을
  연결하기만 하면 되고, 백엔드 변경은 없다.
- **2번**: "몬스터 드랍(부품)이 무조건 나오는데, 몹 숫자가 늘어난 뒤로 일일이
  주우러 다니느라 아침 준비 시간이 부족하다" → 드랍 확률 50%로 낮추고 개수를
  늘려서 보상.
- **5번**: "원거리 무기가 너무 쓸모없다, 에너지로 사는 만큼 성능이 보장돼야
  한다" → `docs/backend/69`(관통·재장전 패치) 이후에도 여전히 부족하다는 확인을
  받아 2차 조정 진행.
- **6번**(스태미너)은 사용자가 "지금은 보류"로 명시적으로 미룸 — 이번 범위 밖.
- **7번**: "몬스터가 60마리 정도로 너무 많다, 40마리 정도로" → 확인 결과 현재
  공식(솔로 1웨이브)이 정확히 63마리라 "60마리"와 일치, 40마리를 목표로 조정.

## 과정

### 1. 부품 드랍 확률 50% + 개수 증가 (피드백 #2)

`monsters.json`의 잡몹/엘리트 6종(`demon`/`hellhound`/`blood`/`eyeball`/
`lava_slime`/`minotaur`)의 `itemDrops[drop_normal]`을 `chance: 1` → `0.5`로
낮추고, `min`/`max`를 대략 2배로 올렸다(예: demon `1~2` → `2~4`, lava_slime
`2~4` → `4~8`). 기대값(확률×평균개수)은 거의 그대로 유지하면서, 바닥에
흩어지는 **개별 픽업 개수**를 줄이는 게 목적이다 — 몹 60마리가 전부 드랍하면
줍는 데만 시간이 든다는 피드백을 "덜 자주, 더 많이"로 푼다.

보스(`boss_demon` 등 4종)의 `drop_normal`은 건드리지 않았다 — 밤에 1마리만
나오는 단일 이벤트라 "많이 주워야 하는" 문제가 애초에 없다. `drop_rare`(3~30%
확률의 희귀 드랍)도 그대로 뒀다 — "무조건" 드랍이 아니라 이미 피드백의 대상이
아니다.

### 2. 몬스터 수 하향 (피드백 #7)

`waves.json`의 `playerScaling.baseMultiplier`를 3→2로 낮췄다. `perPlayer`(인원당
증가폭)와 `base`는 그대로 둬서, 인원수에 따른 상대적 성장 곡선(더 많은 인원 =
더 많은 몹)은 유지하면서 절대량만 낮췄다.

| 인원 | 이전(baseMultiplier=3) 1웨이브 | 이후(baseMultiplier=2) 1웨이브 |
|---|---:|---:|
| 1 | 63 | 41 |
| 2 | 111 | 74 |
| 4 | 207 | 138 |

솔로 41마리로 "40마리 정도"라는 목표에 근접한다.

### 3. 원거리 무기 가성비 2차 조정 (피드백 #5)

`docs/backend/68`(관통) + `69`(재장전 절반)를 적용했는데도 "쓸모없다"는 확인을
받아, 이번엔 **가격 대비 성능**을 직접 계산해 재조정했다. 지표는 "탄창 1회전
DPS ÷ 상점가(`items.json` buyPrice)"로 잡았다(근접은 탄약이 없으므로
damage×fireRate ÷ 가격, 도구류처럼 상점에 없는 무기는 제외):

```
cycleDps = (damage × pellets × magazine) / (magazine/fireRate + reloadTime)
ratio    = cycleDps / buyPrice
```

전체 무기(근접+원거리, 상점 판매분만)를 계산해 정렬한 결과, `rifle`(0.131),
`sniper_rifle`(0.123)이 게임 전체 무기 중 **최하위 1·2위**였고,
`pump_shotgun`(0.194)·`double_barrel_shotgun`(0.198)도 평균 이하였다 — 나머지
원거리 무기(handgun 0.52, shuriken 0.44, minigun 0.31, revolver 0.32 등)는
이미 근접 평균과 비슷하거나 나은 수준이라 손대지 않았다.

이 4종만 골라 "데미지 상승 + 가격 인하"를 반씩 나눠 적용했다(한쪽 레버만 밀면
전투력이 과하게 오르거나 접근성만 좋아지고 실전 위력은 그대로인 문제가 생겨서,
`factor = sqrt(0.25 / 현재비율)`을 데미지엔 곱하고 가격엔 나누는 방식으로 목표
비율 0.25(근접 평균 하위권 수준)에 맞췄다):

| 무기 | 데미지 | 가격 | 비율(전) → (후) |
|---|---|---|---|
| rifle | 42→58 | 150→110 | 0.131 → 0.247 |
| sniper_rifle | 90→128 | 520→365 | 0.123 → 0.249 |
| pump_shotgun(펠릿당) | 12→14 | 480→420 | 0.194 → 0.258 |
| double_barrel_shotgun(펠릿당) | 9→10 | 260→230 | 0.198 → 0.248 |

### 4. 테스트 — 드랍 확률화로 깨진 3개 수정

`world-combat.test.ts`의 "부품 확정 드랍" 전제 테스트 3개가 확률 도입으로
깨졌다(50%라 한 번 죽여서 못 볼 수 있음). 드랍을 볼 때까지 몬스터를 새로
스폰해 재시도하는 방식으로 고쳤다(실패 확률이 0.5ⁿ로 지수적으로 줄어 최대
40회 재시도면 사실상 항상 성공). 재시도를 짜면서 함정을 하나 더 발견했다 —
이전 시도의 `fireWeapon()`이 걸어 둔 무기 쿨다운이 시간이 안 흐른 채 다음
재시도의 발사를 조용히 막았다(`world.tick(1)`로 시간을 흘려보내 해결).
