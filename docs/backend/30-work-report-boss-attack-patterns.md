# 작업 보고서 — 보스 공격 패턴(돌진 예고, 광역 예고) 추가

> 보스 몬스터가 기본 근접 공격만 반복하던 것에, 예고(텔레그래프) 후 발동하는 특수
> 패턴 두 가지를 추가했다: (1) 방향을 예고하고 그 방향으로 빠르게 대시하는 돌진,
> (2) 지점을 예고하고 그 자리에 원형 범위로 즉시 피해를 주는 광역. 둘 다 "미리
> 보여주고 x초 뒤 발동"하는 회피 가능한 패턴이라는 요청 그대로 구현했다.

---

## 1. 기획 — 무엇을, 왜

요청: 보스 공격에 패턴을 추가하자 — ① 돌진 공격(범위 예고 → x초 뒤 돌진), ②
광역 공격(범위 예고 → x초 뒤 그 자리 내려찍기). 예고 시간 등 구체적인 수치는
정해지지 않아서, 이 세션의 다른 밸런스 값들(무기 스탯, 건축 비용 등)과 같은
관례대로 플레이스홀더 값을 직접 정하고 명시했다.

## 2. 과정 — 어떻게 했나

### 2.1 설계 결정

- **예고 지점/방향은 예고 "시작 시점"에 고정**한다. 예고 도중 타겟이 움직여도 범위가
  따라가지 않는다 — 따라가면 "본 대로 피했는데 맞는" 상황이 생겨서 회피 가능한
  패턴이라는 의미가 없어진다.
- **예고 중엔 보스가 완전히 정지**한다. 이동하면서 예고하면 실제 발동 위치와 화면에
  보여준 위험 범위가 어긋난다.
- **막는 건축물/타겟 우선순위 로직(backend/27)과는 별도 경로**로 뒀다. 특수 패턴이
  진행 중이면(`tickBossPattern`이 true를 반환하면) 그 틱의 일반 추격/공격/이동
  로직을 통째로 건너뛴다 — 특수 패턴은 평소 행동을 "대체"하는 것이지 얹는 게 아니다.
- **트리거 조건**: 아그로 반경 안에 타겟이 있고, 특수 패턴 쿨다운이 다 됐을 때. 둘 다
  가능하면(지금은 보스만 둘 다 가짐) 매번 50/50 무작위로 고른다 — 항상 같은 순서로
  나오면 패턴이 아니라 외울 수 있는 순서가 된다.
- **스폰 직후 3초 유예 시간**을 뒀다. 스폰하자마자 바로 예고가 뜨면 상황 파악할
  틈도 없이 위협이 시작돼 불공평하게 느껴진다.
- **돌진은 플레이어만 맞힌다**(코어/건축물 무시, 벽도 그냥 뚫고 지나간다). 몬스터의
  건축물 하드 충돌 자체가 아직 없어서(backend/18 §확정 5) 범위 밖 문제로 남겨뒀다.

### 2.2 데이터 — `monsters.json`/`data/index.ts`

보스 전용으로 `chargeAttack`/`slamAttack` 옵션 필드를 `MonsterDataSchema`에
추가했다(zod 스키마, 다른 데이터 파일과 같은 패턴). 값은 전부 플레이스홀더:

```json
"chargeAttack": { "telegraphSeconds": 1, "speed": 260, "duration": 0.5, "width": 40, "damage": 30, "cooldown": 8 },
"slamAttack": { "telegraphSeconds": 1.3, "radius": 70, "damage": 35, "cooldown": 10 }
```

### 2.3 시뮬레이션 — `World`의 상태 머신

`MonsterEntity`에 `pattern: BossPatternState`(idle → chargeTelegraph → charging →
idle, 또는 idle → slamTelegraph → idle)와 `specialAttackCooldown`을 추가했다.
`chargeAttack`/`slamAttack` 데이터가 없는 타입(잡몹 등)은 `tickBossPattern`이
필드 존재 여부 검사 한 번만 하고 바로 빠져나가서, 일반 몹의 틱 비용은 사실상
그대로다.

- `tryStartBossPattern`: 쿨다운 감소 → 아그로 타겟 탐색(기존
  `resolveAggroTarget` 재사용) → 방향/지점을 고정하고 예고 상태로 전이.
- `tickChargeTelegraph`/`tickSlamTelegraph`: 그 자리에 멈춰 타이머만 감소, 끝나면
  다음 단계로.
- `tickCharging`: 고정된 방향으로 `moveMonster`(기존 군집 분리 로직 그대로 재사용)
  를 빠른 속도로 호출하면서, 경로 폭 안의 플레이어를 원형 판정(`circlesOverlap`,
  기존 근접/투사체 판정과 동일 함수)으로 때린다. `hitPlayerIds`로 한 번의 돌진에
  같은 플레이어를 여러 틱에 걸쳐 중복으로 맞히지 않게 막았다.
- 광역은 예고 종료 즉시 그 지점 반경 안의 플레이어 전원에게 한 번에 피해를 준다.

### 2.4 동기화 — 서버/로컬 → 클라이언트

Colyseus 스키마는 유니온 타입을 못 쓰므로, `pattern` 상태 머신을 그대로 보내는 대신
`describeBossTelegraph(monster, data)` 순수 함수를 만들어 "지금 예고 중이면 보여줄
정보(종류/지점/방향/반경/거리/남은시간/전체시간), 아니면 undefined"로 한 번 눌러
편다. 예고 중이 아닐 때(idle/실제 돌진 실행 중)는 아무것도 안 보낸다 — 돌진이 실제로
실행되는 동안엔 보스가 빠르게 움직이는 모습 자체가 이미 "위험이 시작됐다"는 신호라
별도 경고가 필요 없다.

이 함수 하나를 서버(`GameRoom.syncMonsters`)와 로컬(`LocalConnection`) 양쪽이
그대로 재사용한다 — 두 경로가 각자 계산하면 미묘하게 어긋날 여지가 생기는데, 그걸
원천 차단했다. `MonsterSchema`/`MonsterView`에 `telegraphKind`(빈 문자열 |
'charge' | 'slam')와 좌표/방향/반경/거리/잔여시간 필드를 평평하게 추가했다.

`SnapshotInterpolator`는 별도 수정이 필요 없었다 — 위치가 아닌 필드는 원래도
보간 없이 최신 스냅샷 값을 그대로 들고 오는 구조라(`{...target, x: lerp(...), ...}`),
새 필드도 자동으로 그 경로를 탄다.

### 2.5 렌더링 — `EntityRenderer`

몬스터별로 `telegraphKind`가 있으면 `Graphics` 오브젝트 하나를 만들어(없으면 재사용)
매 스냅샷마다 `clear()` 후 다시 그린다. 예고 진행률(시작 0 → 발동 직전 1)에 따라
채움 투명도를 점점 올려서 "곧 온다"는 긴박감을 준다.

- 광역: `telegraphX/Y` 중심에 `telegraphRadius` 반지름 원.
- 돌진: 시작점에서 `telegraphDirX/Y` 방향으로 `telegraphRange`만큼 뻗은, 폭
  `telegraphRadius*2`짜리 직사각형. 캔버스 회전 명령 대신 네 꼭짓점을 벡터로 직접
  계산해서(`fillPoints`/`strokePoints`) 그렸다 — 좌표를 눈으로 검증하기 쉽다.

## 3. 결과 — 검증

새 테스트 파일 `world-boss.test.ts`(9개) 작성:

- 스폰 직후 유예 시간 동안은 아그로 타겟이 있어도 패턴을 안 씀
- 유예 시간이 지나고 시야각 안에 타겟이 있으면 예고로 전이
- 돌진 예고 중엔 정지, 방향 유지
- 돌진 실행 시 경로 위 플레이어를 정확히 1회만 타격, 종료 후 idle+쿨다운 세팅
- 돌진 경로 밖 플레이어는 안 맞음
- 광역 예고 종료 시 즉시 범위 안 플레이어 타격 + idle 복귀 + 쿨다운
- 광역 범위 밖 플레이어는 안 맞음
- 광역 지점은 예고 시작 시점에 고정(플레이어가 나중에 그 자리를 벗어나면 안전)
- `describeBossTelegraph`가 예고 중에만 값을 주고 idle/charging엔 undefined

wave5(보스 웨이브)로 점프해 다른 몬스터 37마리와 뒤섞인 상태에서 보스 하나만
골라 테스트하다 보니 두 가지 함정을 만나 고쳤다:
1. 지키는 플레이어 없이 방치하면 다른 몬스터들이 코어를 파괴해 `defeat`로
   전환되고 스폰 자체가 멈춰버려서(보스가 아직 큐에 남아있어도) — 보스를 찾는
   탐색 루프 동안 코어 HP를 계속 만피로 되돌려서 우회했다.
2. 아그로 발견은 시야각(120도) 검사를 거치므로, 테스트에서 플레이어를 아무 방향에나
   놓으면 우연히 시야 밖일 수 있다 — 보스의 실제 `facingX/Y` 방향 바로 앞에 놓도록
   고쳤다.

```bash
pnpm --filter @dropfall/shared test     # 137 passed(기존 128 + 신규 9), 5회 연속 안정
pnpm typecheck                          # client/server 전체 통과
pnpm lint                               # 에러 0
pnpm build                              # client(vite)/server(tsup) 전체 통과
```

브라우저(Playwright, 오프라인 로컬 모드)로도 wave5까지 점프해서 실제로 큰 보스가
스폰되는 것과 코어 방어 UI 흐름을 확인했다 — 사용자가 직접 웹에서 돌진/광역 예고
표시와 발동까지 확인 완료.

## 4. 다음 작업

- 예고 시간/속도/데미지/쿨다운 등은 전부 플레이스홀더다. 실제 플레이 감각(회피
  가능한 난이도인지)을 보고 조정이 필요할 수 있다.
- 돌진은 건축물을 무시하고 그냥 통과한다 — 몬스터-건축물 하드 충돌 자체가 아직
  없어서(backend/18 §확정 5, 범위 밖) 발생하는 자연스러운 한계다. 나중에 그 하드
  충돌이 생기면 돌진도 같이 막히게 손볼 여지가 있다.
- 지금은 패턴이 두 종류뿐이라 50/50 무작위지만, 패턴이 늘어나면 가중치나 체력 구간별
  패턴 전환 같은 확장이 필요할 수 있다.
- 텔레그래프 표시는 보스 전용으로만 만들었다 — 다른 몬스터 타입에 특수 패턴이
  생기면 `chargeAttack`/`slamAttack`을 그 타입 데이터에도 추가하기만 하면
  `tickBossPattern`/`describeBossTelegraph`가 타입 무관하게 그대로 동작한다(이름은
  "보스"지만 실제로는 어떤 몬스터 타입에도 적용 가능한 범용 구조다).
