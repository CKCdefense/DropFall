# 백엔드/서버 개발 기획서 (예선 데모용)

> 이 문서는 [로드맵](../04-roadmap.md)의 8주 정식 일정을 **예선 데모(1~2주)** 기준으로
> 압축한 것이다. 담당: **역할 A — 서버/네트워크** (`server/`, `shared/sim`, `client/net`).
> 기존 로드맵/기술명세는 수정하지 않고 그대로 참조한다. 실제 제출일이 확정되면
> Day 표기를 절대 날짜로 갱신한다.

---

## 1. 전제

- 실제 3인 팀, 예선 마감까지 **1~2주(7~10 작업일)**
- **멀티플레이는 처음부터 포함** — 협동 디펜스라는 컨셉 자체가 멀티 없이는 성립하지 않는다
- "완성 > 기능 수" 원칙([로드맵](../04-roadmap.md) 개발 원칙 1) 그대로 적용 → 서버 쪽도
  **P0만 확실히**, 그 외는 시간이 남을 때만

---

## 2. 범위 재정의 (서버 담당 관점)

[로드맵 §범위 조정 우선순위](../04-roadmap.md)를 서버 영역으로 필터링한 것.

### P0 — 사수 (예선 통과의 필요조건)
- Colyseus 룸 생성/입장 (최대 4인)
- 서버 권위 이동 처리 + 스냅샷 델타 전송
- 몬스터 웨이브 서버 스폰 로직 (`waves.json` 기반)
- Flow Field 이동 AI (BFS 거리맵)
- 서버 히트 판정 (사격 → 데미지)
- 코어 HP 서버 판정, 승패 판정
- 낮/밤 사이클 서버 타이머 (클라는 표시만, 기준 시계는 서버)

### P1 — 여유되면
- 재접속 (`allowReconnection`) — 문서는 "공모전 시연 중 사고 대비로 필수"라고 되어 있으나,
  1~2주 압축 일정에서는 **P0 완성 후 시간이 남으면**으로 낮춘다. 다만 시연 중 리스크가 크므로
  D8-9 여유가 있으면 최우선으로 다시 끌어올린다.
- 다운/부활 서버 로직

### P2 — 이번 데모에서 제외
- 랙 보상(lag compensation) — 애초에 기술명세도 MVP 밖으로 명시
- ECS 전환 — 엔티티 5~6종이면 불필요 ([기술명세 §3.1](../02-tech-spec.md))
- 보스 AI, 원거리/탱커 몬스터의 정교한 행동 트리 — 잡몹+돌진형 정도로 축소 가능

## 3. Day-by-Day 계획

다른 역할과의 의존관계를 `→` 로 표기. B=게임플레이, C=클라/아트/UI.

### D1 — 서버 부팅
- `packages/server` Colyseus 부트스트랩, `packages/shared/sim` 틱 루프 스켈레톤
- `GameRoom`: onCreate/onJoin/onLeave, 20Hz 틱으로 `shared/sim` world 실행
- **B/C에게 필요한 것**: 이 시점에 `shared/protocol` 메시지 타입(입력 스키마)을 먼저 확정해서
  공유해야 B/C가 자기 쪽 스텁을 붙일 수 있음 → **D1 내에 protocol 타입부터 끝낸다**
- 산출물: `pnpm dev` 시 클라가 룸에 join되는 로그만 찍히는 상태

### D2-3 — 멀티 동기화 (최대 리스크 구간, [기술명세 §11](../02-tech-spec.md) 1순위 리스크)
- 입력(이동벡터, 조준각, seq) → 서버 권위 이동 → 스냅샷 델타 → 클라 보간
- 자기 캐릭터만 예측 + 재조정(reconciliation), 타 플레이어/몬스터는 100ms 보간
- 로비: 방 생성/입장 (직업 선택 UI는 C 담당, 서버는 좌석 배정 로직만)
- **여기서 막히면 이후 전부 밀린다.** 압축 일정이라 배정된 여유가 거의 없음 —
  D3 저녁까지 "다른 브라우저 탭 2개로 같은 맵에서 동시에 움직인다"가 안 되면
  즉시 팀에 알리고 D4 계획(전투) 착수를 미루는 결정을 그날 안에 내린다.

### D4-5 — 전투 · 몬스터
- 조준/사격 입력 처리, 투사체 서버 시뮬레이션, 서버 히트 판정
- 몬스터 스폰 (`waves.json`) + Flow Field 이동
- 코어 HP, 웨이브 1~3, 낮/밤 사이클 타이머
- **B와의 접점**: `combat.ts`(데미지 계산, 무기 스탯)는 B 담당, `movement.ts`/`ai/flowField.ts`는
  A 담당 — [로드맵의 파일 단위 분담](../04-roadmap.md#역할-분담-3인) 그대로

### D6-7 — 건축 연동
- `blocksMovement` / `blocksProjectile` 2레이어 그리드 갱신을 Flow Field 재계산과 연결
- 건축물 설치/파괴 이벤트 시에만 재계산 (매 틱 금지, [기술명세 §5.1](../02-tech-spec.md))
- **B가 건축 로직(`building.ts`) 구현 → A는 그 이벤트를 받아 필드 재계산 트리거만 건다.**
  이 부분은 B의 D6-7 작업과 병렬로 진행되므로 인터페이스(이벤트 이름/페이로드)를 D5까지 합의해둔다.

### D8-9 — 배포 · 안정화
- 홈서버: Colyseus + Cloudflare Tunnel + systemd 등록 (`Restart=always`)
- 외부망(모바일 핫스팟 등)에서 Pages URL 접속 → 홈서버 연결 확인
- 3인 동시 접속 20분 이상 유지 테스트 (Cloudflare WebSocket idle timeout 실측,
  [기술명세 §9.3 주의사항](../02-tech-spec.md) — 약 100초에 끊기는 이슈 확인 필요)
- 여유 있으면 P1(재접속) 착수

### D10 — 코드 동결 전 점검
- 홈서버 **재부팅 후** 자동 기동 확인 (실제로 재부팅 테스트, 안 하면 시연 당일 사고)
- 로비 장시간 대기 시 연결 유지 확인
- 서버 틱 처리 시간 프로파일링 (< 10ms/tick 목표, [기술명세 §8](../02-tech-spec.md))

## 4. 기술 결정 요약 (서버 관련, 상세는 [기술명세](../02-tech-spec.md) 참조)

| 항목 | 결정 | 근거 문서 |
|---|---|---|
| 서버 틱 | 60Hz(20Hz에서 상향, [backend/13](13-work-report-tick-rate-60hz.md)), 권위 100% | §4.1 |
| 예측/보간 | 스펙은 "자기 캐릭터만 예측 + 나머지 보간"이지만, 현재 구현([backend/12](12-work-report-snapshot-interpolation.md))은 예측 없이 전원 보간(2틱 지연) — 자기 캐릭터 예측은 아직 미착수 | §4.2 |
| 히트 판정 | 서버에서만, 클라는 이펙트만 즉시 표시 | §4.2 |
| 대역폭 | 정수 픽셀 양자화, 각도 1바이트, AOI 컬링 | §4.3 |
| AI | Flow Field (BFS 거리맵 + 개체당 O(1) 조회), 재계산은 이벤트 기반 | §5 |
| 재접속 | `allowReconnection`, 30초 유예 | §4.4 |
| 배포 | 홈서버 Colyseus, Cloudflare Tunnel로 `wss://` 노출 | §9 |

## 5. B/C 역할과의 인터페이스 계약

- **`shared/sim` 파일 분담**: A = `world.ts`, `movement.ts`, `ai/flowField.ts` / B = `combat.ts`,
  `building.ts`, `wave.ts` ([로드맵 §역할분담](../04-roadmap.md#역할-분담-3인))
- **먼저 확정해야 병목이 없는 것**: `shared/protocol`의 메시지 타입 — B/C가 각자 스텁을 짜려면
  A가 D1에 입력/스냅샷 메시지 스키마를 먼저 내놔야 한다. 이게 늦어지면 B/C도 같이 밀린다.
- **건축 ↔ Flow Field 연동**(D6-7): B가 이벤트를 쏘고 A가 받는 구조. 이벤트 이름/페이로드는
  D5까지 합의.
- **디자인 상수**(TILE_SIZE, TICK_RATE 등)는 `shared/constants.ts`에 A가 D1에 확정 →
  이후 변경 시 전원에게 공지 (특히 TILE_SIZE는 C의 아트 작업에 직결)

## 6. 리스크 & 완화

| 리스크 | 영향 | 완화 |
|---|---|---|
| 멀티 동기화 지연 (D2-3) | 치명적 — 압축 일정이라 밀릴 여유 없음 | D3 저녁 마감으로 스스로 데드라인 걸기. 안 되면 그날 안에 범위 재조정 결정 |
| 홈서버 단일 장애점 | 높음 | systemd `Restart=always`, 부팅 자동 기동. **D10 이전에 재부팅 테스트 최소 1회 실행** |
| Cloudflare Tunnel idle timeout (~100초) | 중간 | 로비 장시간 대기 시나리오 D8-9에 실측. Colyseus ping/pong으로 커버되는지 확인 |
| HTTPS↔WSS 불일치 | 중간 | Pages는 HTTPS 강제이므로 홈서버는 반드시 유효 TLS + `wss://`. D8에 외부망 리허설로 조기 발견 |
| Flow Field 재계산 부하 | 낮음 | 이벤트 기반 재계산 + debounce. 문제 시 웨이브 시작 시점으로만 제한 |
