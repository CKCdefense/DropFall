# 작업 보고서 — 몬스터 히트박스 버그 수정 + 자원채집 시스템 재설계(근접 타격 + 코어 입고)

> 세 가지를 한 번에 처리했다: ① 몬스터 히트박스가 화면상 네모칸과 안 맞는 버그
> 수정, ② "자원 노드에 서서 E 반복" 채집을 "도구로 직접 타격해서 고갈시키고,
> 코어 앞에서 E로 입고"하는 방식으로 전면 재설계, ③ 코어 상호작용 모달 4종(다른
> 작업자가 미리 만들어 둔 UI 셸)을 실제로 열리게 배선. 모달 UI 자체는 백그라운드
> 작업자가 병렬로 만들었고, 이 문서는 그 통합과 나머지 두 작업을 다룬다.

---

## 1. 기획 — 무엇을, 왜

세 가지 요청을 동시에 받았다:
1. "몬스터 히트박스가 네모칸이랑 맞지 않는다(플레이 경험상 살짝 위에 있는 것 같다)."
2. "채집 도구가 도입됐으니, 자원 엔티티를 크게 하고 직접 타격(근접무기)해서 체력
   0이 되면 자원 획득 → 코어에 근접해 E로 상호작용하면 팀 공유 자원이 늘어나는
   방식으로 바꾸자."
3. "코어 상호작용(업그레이드/코어 수리/상점) 모달도 미리 만들어 두자."

②는 특히 기존 경제 구조를 건드리는 변경이라, 착수 전에 사용자에게 한 가지를
확인했다: 건축 비용도 팀 공유 자원 풀에서 나가도록 바꿀지("응, 건축 비용도 공유
풀에서 차감") — 답을 받고 나서 `placeBuilding`의 자원 출처 자체를 바꿨다.

## 2. 과정 — 어떻게 했나

### 2.1 몬스터 히트박스 버그(①)

코드를 뜯어보니 렌더링 좌표와 판정 좌표에 오프셋 차이는 없었다(둘 다 정확히
`monster.x/y`를 그대로 쓴다). 진짜 문제는 **크기**였다: 클라이언트
`EntityRenderer.ts`의 `MONSTER_STYLE`이 타입별로 각자 다른 시각적 정사각형 크기를
갖고 있었는데, 실제 판정(`applyMeleeHit`/`projectileHitsMonster`)은 전부 고정값
`HIT_RADIUS=10`을 썼다. trash/rusher/ranged는 그림(반경 4.5~5px)보다 판정
반경(10px)이 2배 넓었고, boss만 반대로 판정이 그림보다 좁았다 — "그림과 판정이
따로 논다"는 게 정확한 원인이었다.

고쳤다: `monstersData`에 타입별 `hitRadius`를 추가하고(trash/ranged=5, rusher=5,
tanker=8, boss=12), `applyMeleeHit`/`projectileHitsMonster`가 이 값을 직접
읽도록 바꿨다. 클라이언트 쪽 `MONSTER_STYLE`에서는 `size`를 아예 없애고
`monstersData[type].hitRadius * 2`로 시각적 크기를 계산하게 했다 — 이제 그림과
판정이 같은 값에서 파생되므로 구조적으로 어긋날 수 없다.

### 2.2 자원채집 재설계(②) — 가장 큰 변경

**데이터**: `resources.json`을 `harvestRadius`/`harvestInterval`/`maxHarvests`/
`yieldPerHarvest` 조합에서 `hitRadius`/`hp`/`yieldOnDeplete`로 갈아엎었다.
`hp`는 도구 데미지의 정수배로 잡아서 "일정 횟수 타격"이 실제로 딱 떨어지게 했다
(나무 hp=54 = 도끼 데미지 18 × 3회, 돌 hp=42 = 곡괭이 데미지 14 × 3회).
`yieldOnDeplete`는 기존 총량(나무 5×5=25, 돌 3×3=9)을 그대로 보존해서 밸런스
연속성을 유지했다. `hitRadius=14`(지름 28px)로 노드 자체도 커졌다 — 몬스터와
같은 이유로 렌더링 크기를 이 값에서 그대로 계산한다.

**도구 이름 불일치 발견/수정**: `resources.json`/`tools.json`은 곡괭이를
`pickaxe`로, 반면 실제 무기 시스템(`items.json`/`weapons.json`)은 `pickax`로
쓰고 있었다 — 지금까지는 도구 일치 검사 자체가 없어서 드러나지 않았던 잠재
버그였다. 이번에 `requiredTool`을 실제로 강제하게 되면서 그대로 뒀으면 돌 채집이
영구히 막힐 뻔했다 — `pickax`로 통일했다.

**타격 로직**: `World.harvest()`(반경 스캔 + E 홀드)를 통째로 지우고,
`fireWeapon()`이 몬스터 판정(`applyMeleeHit`)과 나란히
`applyMeleeHitToResourceNode()`를 호출하도록 했다. 이 메서드는 몬스터 판정과
똑같이 `withinMeleeArc`를 재사용하되, 규칙이 다르다: (a) `requiredTool`과 장착
무기가 정확히 일치해야 하고(도끼로 돌은 못 캔다), (b) 광역이 아니라 **가장 가까운
노드 하나만** 맞는다(군집으로 뭉쳐 있어서 광역으로 캐면 채집이 무의미해진다).
hp가 0이 되는 순간 `yieldOnDeplete`를 그 자리에서 때린 플레이어에게 지급한다
(히트당 지급이 아니라 고갈 시 일괄 지급).

**공유 자원 풀**: `CoreState`에 `sharedWood`/`sharedStone`을 추가했다.
`player.wood`/`player.stone`은 의미가 바뀌었다 — 더는 "내가 가진 자원"이 아니라
"아직 코어에 안 넣은, 손에 든 자원"이다. 새 메서드 `depositAtCore(playerId)`가
코어 반경(`CORE_INTERACT_RADIUS = CORE_RADIUS+32 = 48px`) 안에서 플레이어의
휴대량을 공유 풀로 옮기고 개인 지갑을 0으로 되돌린다. `placeBuilding`은 이제
`player.wood/stone`이 아니라 `this.core.sharedWood/sharedStone`을 검사·차감한다.

**E 키 재배선**: `InputController`의 `harvest`(홀드 재전송) 로직을 완전히
지우고, E를 `deposit()`(단발 액션, `on('down')`)으로 바꿨다. 채집 자체는 이제
기존 좌클릭 공격 경로 그대로다 — 도구를 장착하고 자원 노드를 향해 공격하면 된다.
서버 메시지 이름도 `harvest` → `deposit`으로 바꿨다(의미가 완전히 달라졌는데
이름만 남기면 나중에 읽는 사람이 헷갈린다).

**HUD**: 코어 패널에 "공유 나무/돌" 줄을 추가하고, 기존 "나무/돌" 표시는 "휴대
나무/돌"로 이름을 바꿔서 두 값이 다른 개념임을 분명히 했다. 하단 조작 안내도
"[E] 채집" → "[E] 코어 입고"로 바뀌었다.

**렌더링**: `EntityRenderer`의 자원 노드에 몬스터/건축물과 같은 HP 바(맞았을
때만 보임)를 추가하고, 시각 크기를 `resourcesData[type].hitRadius`에서 계산하게
했다(①과 같은 원칙).

### 2.3 코어 모달 통합(③)

배경 작업자가 `packages/client/src/game/ui/`에 `Modal.ts`(공용 뼈대) +
`CoreModal`/`UpgradeModal`/`StoreModal`/`CraftModal`을 순수 Phaser
GameObject로 미리 만들어 뒀다(자세한 내용은 `docs/frontend/09`). 이 문서에서는
그걸 실제로 켜지게 배선했다:

- `HudScene`에 4개 모달을 인스턴스화하고, `CoreModal`의 `onManage`/`onStore`/
  `onCraft`를 각각 `UpgradeModal`/`StoreModal`/`CraftModal`의 `open()`으로
  연결했다(코어 모달을 먼저 닫고 목적지 모달을 연다). `onWarehouse`는 아직
  대응하는 모달이 없어서(와이어프레임이 거기서 잘려 있었다) 로그만 남긴다.
- `F` 키를 눌러 코어 모달을 열고 닫는다. **의도적으로 코어 근접 판정을 걸지
  않았다** — 아직 실제 효과(경제/티어 로직)가 없는 선작업 UI라 지금 막을 이유가
  없고, 나중에 진짜 기능이 붙으면 그때 근접 판정을 추가하면 된다(§4에 명시).

## 3. 결과 — 검증

`world-building.test.ts`의 "채집" describe 블록을 전면 재작성했다(반경+E 홀드
전제였던 기존 테스트 15개가 다 깨졌다 — 새 근접 타격 API에 맞춰 새로 짰다). 새로
추가/재작성한 테스트:
- 맞는 도구로 노드를 때리면 hp가 깎이고, 고갈 순간 한 번에 자원이 지급된다.
- 도구가 안 맞으면(도끼로 돌) 데미지가 안 들어간다.
- 사거리 밖 노드는 안 맞는다.
- 고갈된 노드는 공격해도 반응 없고, respawnSeconds 후 hp가 원상복구된다.
- 코어 입고: 반경 안/밖, 들고 있는 게 없을 때, 여러 플레이어가 같은 풀에
  누적되는지.
- 건축 관련 기존 테스트 전부를 "공유 풀에서 차감" 기준으로 다시 씀
  (`grantSharedResources` 헬퍼로 `world.getCore()`를 직접 채워 넣는 방식,
  기존 세션에서 코어 HP를 직접 조작하던 디버그 캐스팅과 같은 패턴).

```bash
pnpm --filter @dropfall/shared test     # 178 passed(기존 158 + 신규/수정 20), 5회 연속 안정
pnpm typecheck                          # client/server 전체 통과
pnpm lint                               # 에러 0
pnpm build                              # client(vite)/server(tsup) 전체 통과
```

Playwright로 실제 브라우저에서 전체 흐름을 끝까지 확인했다: 도끼 장착 → 나무
노드 3타 → 휴대 나무 25 지급 확인(HP 바가 타격마다 줄어드는 것도 확인) → 코어
앞에서 E → 공유 나무 25로 이동, 휴대 나무 0으로 리셋 확인. F 키로 코어 모달이
열리고, "상점" 버튼을 누르면 코어 모달이 닫히고 상점 모달이 열리는 것도 확인했다.

(테스트 중 실시간 상호작용에 도구 호출 왕복 시간이 누적되면서 dayDuration(90초)이
실제로 다 지나가 버려 몇 차례 코어가 무너지는 일이 있었다 — 기능 자체의 문제가
아니라 수동 브라우저 테스트의 특성이라 반복 재시도로 우회했다.)

## 4. 다음 작업

- 몬스터 히트박스 값(trash/rusher=5, tanker=8, boss=12)은 전부 플레이스홀더다.
  실제 스프라이트가 들어오면 시각적 크기와 맞춰 재조정이 필요할 수 있다.
- 코어 모달들은 여전히 데이터가 없는 선작업 상태다(가격/자원/에너지/티어 전부
  `-`/`0`/`1` placeholder). 실제 업그레이드/상점/제작 경제가 정해지면
  `addRow`가 반환하는 `Text`에 값을 채우고, 각 `on*` 콜백에 실제 로직을 붙이면
  된다.
- "창고" 목적지 모달은 아직 없다 — 필요해지면 `UpgradeModal.ts`와 같은 구조로
  추가하면 된다.
- `F` 키로 코어 모달을 여는 데 코어 근접 판정이 없다 — 지금은 어디서든 열린다.
  실제 코어 상호작용 기능이 붙으면 `depositAtCore`가 쓰는
  `CORE_INTERACT_RADIUS`를 재사용해서 근접 판정을 추가하는 게 자연스럽다.
- 여러 플레이어가 동시에 같은 자원 노드를 타격하는 협동 채집은 자연스럽게
  동작한다(공유 hp 풀이라 몬스터 협동 사냥과 동일한 방식) — 다만 마지막 타격을
  넣은 사람만 `yieldOnDeplete`를 받는다. "기여도 분배" 같은 규칙은 이번 범위
  밖이다.
