# 70. 제작 결과 쌓기 (작업 보고)

제작 결과 칸이 한 번 차면 꺼내 가기 전까지 다음 제작을 걸 수 없었다. 울타리는 한 번에
여섯 개씩 나오는데 스무 개를 두르려면 네 번을 만들어야 하고, 그때마다 꺼내 옮겨야 했다 —
**제작 시간보다 정리하는 시간이 길었다.**

## 1. 같은 물건이면 쌓는다

결과 칸이 차 있어도 **같은 물건이면** 이어서 만들 수 있다. 상한은 한 칸에 100개다
(`crafting.json`의 `outputStackLimit`).

- **다른 물건이면 여전히 거절한다.** 섞어 쌓으면 앞의 결과가 무엇이었는지 사라진다.
- **부분적으로는 받지 않는다.** 여섯 개 중 두 개만 담기면 나머지 넷이 어디로 갔는지
  설명할 길이 없다. 자리가 모자라면 아예 시작하지 않아서 **비용도 나가지 않는다.**
- 만드는 도중에 결과를 꺼내 갔을 수 있으므로, 완성 시점에 "같은 물건인가"를 다시 본다.

100은 아이템 자체의 `stackSize`(울타리 20)와 **별개**다. 꺼낼 때는 인벤토리·창고 각 칸의
`stackSize`를 그대로 지키므로 소지 규칙은 달라지지 않는다 — 제작 칸만 넉넉한 것이다.

## 2. 같이 고친 것 — 되돌리는 길이 막혀 있었다

제작 칸은 "넣을 수 없는 칸"이라 `placeAt`이 들어온 것을 **그대로 되돌려서** 거절하고
있었다. 그런데 그 자리는 `moveItem`에서 **다 못 들어간 나머지를 원래 자리로 되돌리는**
경로와 같은 문이다.

결과를 인벤토리로 끌어다 놓을 때 스택 상한에 걸려 일부만 들어가면, 나머지가 거절당해
**조용히 사라졌다.** 결과가 6개일 때는 좀처럼 드러나지 않았지만(빈 칸에 놓으면 통째로
들어간다) 한 칸에 100개까지 쌓이는 지금은 흔한 일이 된다.

넣는 이동과 되돌리는 이동을 갈랐다.

| 경로 | 처리 |
|---|---|
| 플레이어가 제작 칸으로 옮김 | `moveItem`이 **시작 전에** 막는다 |
| 다 못 들어간 나머지 되돌리기 | `placeAt`이 받는다(비었으면 놓고, 같은 물건이면 합친다) |

## 3. 검증

- 신규 4개 통과 — 같은 물건은 쌓이고(6 → 12), 다른 물건은 거절되며 비용도 안 나가고,
  상한까지 찬 칸에는 시작조차 안 되고, 꺼낼 때 나머지가 사라지지 않는다.
  기존 "꺼내 가기 전에는 다음 제작을 걸 수 없다"는 새 규칙으로 바꿔 썼다
- 헤드리스 크롬: 울타리 제작을 세 번 연속 누르면 결과 칸이 6 → 12 → 18로 쌓인다

## 4. 남은 것

- 상한에 걸려 거절될 때 **화면에 아무 표시가 없다.** 자원이 모자랄 때와 구분이 안 된다 —
  충전 칸의 붉은 테두리 깜빡임(§backend/57)과 같은 신호가 필요하다
- 100개를 인벤토리로 끌면 한 칸(20개)만 채우고 나머지 80개가 제작 칸에 남는다. 여러 칸에
  나눠 담으려면 quickMove 같은 별도 조작이 있어야 한다
