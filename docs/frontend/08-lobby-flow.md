# 게임 로비(대기실) 흐름과 규격

## 1. 화면 전환

```
타이틀 / 방 목록          대기실                     인게임
(LobbyApp, DOM)   →   (WaitingRoom, DOM)   →   (Phaser)
                        phase = lobby           phase = playing
```

**방에 들어가는 것과 게임이 시작되는 것은 별개다.** 방 입장은 Colyseus 연결,
게임 시작은 서버 상태(`phase`)의 전환이다. `main.ts`가 이 두 단계를 나눠 관리한다.

- 방 입장 성공 → `WaitingRoom` 표시
- 서버 `phase`가 `playing`이 되면 → 대기실을 닫고 Phaser 기동
- `ESC` 또는 [나가기] → 방을 떠나고 타이틀로

> **오프라인 모드(`?local=1`)는 대기실을 건너뛴다.** 혼자라 준비할 상대가 없다.
> `LocalConnection.getLobbyView()`가 처음부터 `phase: playing`을 돌려준다.

## 2. 서버 상태

`GameRoomState`에 추가된 것:

```ts
phase: 'lobby' | 'playing'   // RoomPhase
hostSessionId: string        // 첫 입장자. 나가면 남은 사람 중 첫 번째에게 넘어간다
```

`PlayerSchema`에 추가된 것:

```ts
job: string       // JobId. 선택 전에는 빈 문자열
isReady: boolean
```

## 3. 메시지

| 메시지 | 페이로드 | 서버 검증 |
|---|---|---|
| `selectJob` | `{ job: JobId }` | 대기실 단계인지, 유효한 JobId인지 |
| `setReady` | `{ ready: boolean }` | 대기실 단계인지, **직업을 골랐는지** |
| `startGame` | — | 대기실 단계인지, **방장인지**, 전원이 직업+준비를 마쳤는지 |

거절되면 서버가 `lobbyError` 메시지로 사유 문자열을 보낸다
(`StartRejectReason`). 클라이언트가 버튼을 비활성화해도 타이밍 차이로 요청이
들어올 수 있어 **서버가 최종 판정한다.**

### 결정 사항

- **방장만 시작할 수 있다.** 와이어프레임의 "Ready/Start" 표기대로, 방장은 [시작],
  나머지는 [준비] 버튼을 본다
- **방장 자신은 준비를 요구하지 않는다.** 시작 버튼이 곧 준비 의사 표시다
- **직업을 바꾸면 준비가 풀린다.** 준비한 채로 직업을 바꾸면 팀 구성이 조용히
  달라져서, 다른 사람이 인지하지 못한 채 시작될 수 있다
- **직업 없이는 준비할 수 없다.** 클라이언트에서도 버튼을 비활성화한다
- **시작하면 방을 잠근다**(`lock()`). 진행 중인 게임에 난입해 대기실 상태를
  보게 되는 상황을 막는다

## 4. 직업

MVP 3종 ([기획서 §5](../01-game-design.md)). 정의는
[shared/protocol/lobby.ts](../../packages/shared/src/protocol/lobby.ts)에 있다.

| id | 이름 | 역할 |
|---|---|---|
| `engineer` | 정비공 | 건축·수리 |
| `medic` | 의사 | 치유·부활 |
| `soldier` | 군인 | 화력 |

**아직 게임플레이에 반영되지 않는다.** 선택 값만 동기화하고 있고, 패시브/액티브는
전투가 들어올 때 붙인다.

## 5. 방 코드 입력 모달

와이어프레임대로 방 코드를 **한 글자씩 4칸**으로 받는다
([codeInput.ts](../../packages/client/src/ui/codeInput.ts)).

칸을 나누면 자릿수가 눈에 보여 오타가 줄지만, 그만큼 입력 편의를 직접 챙겨야 한다.
안 하면 나눠놓은 게 오히려 불편해진다:

- 한 글자 입력하면 자동으로 다음 칸
- 빈 칸에서 백스페이스 → 이전 칸으로 이동하며 지움
- 좌우 방향키로 칸 이동
- **붙여넣기 한 번에 4칸 채우기**
- 코드 알파벳에 없는 글자(`0`, `O`, `1`, `I` 등)는 아예 입력되지 않는다
- 4칸을 채우면 비밀번호 칸으로 자동 이동, 비밀번호에서 Enter로 참가

## 6. 아직 안 된 것

- **채팅** — 와이어프레임에 "(MVP 제외)"로 표기돼 있어 영역만 잡아뒀다
- **캐릭터 초상화** — 슬롯의 사각형은 플레이스홀더다. 직업별 스프라이트가 나오면
  `.asset` 슬롯으로 교체한다
- **직업 중복 제한** — 지금은 네 명이 모두 같은 직업을 고를 수 있다.
  [기획서](../01-game-design.md)의 "어떤 직업도 단독으로 웨이브를 못 넘긴다"는
  밸런스 원칙과 충돌할 수 있어 플레이테스트 후 정한다
- **재접속 복귀** — `allowReconnection` 미구현. 게임 중 끊기면 그대로 나간다
