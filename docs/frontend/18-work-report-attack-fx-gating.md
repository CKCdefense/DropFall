# 18. 공격 연출이 쿨다운을 안 지키던 문제 (작업 보고)

연타하면 실제로 나가지도 않는 공격의 휘두르기·총구 화염이 매번 나오던 버그를 고쳤다.
같이 제보된 "몬스터 피격 애니메이션이 사라졌다"는 확인 결과 **버그가 아니었다.**

## 1. 몬스터 피격 애니메이션 — 정상이다

애니메이션 전이를 프레임마다 찍어 봤다.

```
attack → walk → idle → hurt → idle → hurt → attack → idle → hurt
```

`hurt`가 정상적으로 끼어든다. 안 보였던 이유는 **몽둥이로 데몬을 때리면 한 방에 죽어서**다
— 데몬 체력 20, 몽둥이 14 + 공격력 스탯이라 첫 타에 사망 애니메이션으로 넘어간다.
체력이 많은 몬스터(미노타우로스 160)로는 흰색 플래시와 함께 피격 모션이 그대로 나온다.

## 2. 연출이 쿨다운을 안 지켰다

`updateFire`가 **버튼을 뗄 때마다 발사 타이머를 0으로 되돌리고** 있었다.

```ts
if (this.buildMode !== 'off' || !pointer.leftButtonDown()) {
  this.fireTimer = 0;   // ← 여기
  return;
}
```

홀드 연사에는 맞는 코드였지만, 클릭을 떼는 순간 쿨다운이 사라지므로 **빠르게 연타하면
매 클릭마다 연출이 나갔다.** 서버는 그중 하나만 받아들이니, 화면만 대여섯 번 번쩍이고
실제 피해는 한 번 들어간다.

같은 이유로 **재장전 중·빈 탄창**에도 총구 화염이 나왔다. 클라이언트가 그 상태를 아예
안 보고 있었다.

## 3. 고친 방식

연출을 서버 응답에 맡기지 않았다 — 타격감은 지연되면 안 된다. 대신 클라이언트가
**서버보다 너그럽지 않게** 판단하도록 관문을 맞췄다.

- 발사 타이머를 버튼 상태와 무관하게 계속 흘려보낸다. 무기별로 다음 발사 가능 시각을
  들고 있다 — 서버 `CooldownTracker`가 (플레이어, 무기)별인 것과 같은 단위다.
- 스냅샷으로 알 수 있는 것을 먼저 거른다: 쓰러짐(`hp <= 0`), 재장전(`reloadRemaining > 0`),
  빈 탄창(`ammoMagazine > 0 && ammo <= 0`).
- 서버가 쓰는 여유(`FIRE_COOLDOWN_GRACE`)는 **일부러 안 쓴다.** 클라이언트가 더
  너그러우면 헛연출이 다시 생긴다.

건축물 설치는 예전에 타이머를 `Infinity`로 막았는데, 타이머가 계속 흐르게 되면서 그
수법을 못 쓴다 — "이번에 누른 동안 이미 놓았는지"를 따로 기억하는 방식으로 바꿨다.

## 4. 검증

- 몽둥이(1.1발/초)로 **2초에 12번 연타** → 연출 **3회**, 간격 940·963ms
  (고치기 전에는 12회 전부 나왔다)
- 권총 **4초 홀드** → 210ms 간격으로 12발 → **979ms 동안 연출 없음**(재장전) → 재개
- shared 536 + server 31 통과, typecheck·lint 깨끗

## 5. 남은 것

- 판정이 두 곳(서버 `World.fireWeapon`, 클라 `canAttack`)에 있다. 점사(burst)나 산탄처럼
  발사 **내부**가 갈리는 규칙은 클라가 보지 않는다 — 그쪽은 연출이 한 번 나가는 건
  똑같아서 지금은 어긋날 일이 없지만, 발사 여부를 가르는 조건이 새로 생기면 양쪽을
  같이 고쳐야 한다.
