# 14. 하단 바 확대와 캐릭터 정보 창 (작업 보고)

화면 아래 퀵슬롯을 3배 가까이 키우면서 **직업/스탯 버튼 + 체력·스태미나 막대**를 한
덩어리로 묶고, 그 버튼이 여는 **캐릭터 정보 창**을 새로 만들었다.

## 1. 하단 바

와이어프레임 구조 그대로다.

```
        [ 체력 ────────── ][ 스태미나 ──────── ]
[직업/스탯][ 인벤 1 ][ 인벤 2 ][ 인벤 3 ][ 인벤 4 ]
```

- 칸 크기 **40 → 116**. 예전엔 아이콘이 30px밖에 안 돼서 무엇을 들었는지 구분이 어려웠다.
- **막대를 바 안으로 들였다.** 체력·스태미나는 "지금 내 몸 상태"라 손에 든 것과 한
  덩어리로 읽혀야 한다. 예전엔 얇은 체력 바가 칸 위에 따로 떠 있어 시선이 두 번 갔다.
  막대에 숫자(`체력 100 / 100`)도 같이 적는다 — 최대치가 직업·음식으로 달라지므로
  길이만으로는 얼마인지 알 수 없다.
- 스태미나 막대는 이번에 처음 화면에 나왔다. 데이터는 이미 내려오고 있었다(53번 보고서).

## 2. 캐릭터 정보 창

와이어프레임대로 초상화·이름·스탯 세 줄·스킬·설명을 배치했다. 초상화는 아틀라스의 직업
스프라이트를 4배로 키워 쓴다.

**레벨과 스킬은 아직 없다.** 그래도 자리를 먼저 잡은 이유는, 스탯을 어디서 보는지가
정해져야 하단 바의 직업/스탯 버튼과 이어지기 때문이다. 아직 동작하지 않는 것
(`Lv -`, `SP 0`, `[+]`, `Unlock`)은 **흐리게 두고 입력을 꺼 뒀다** — 눌리는 것처럼
보이는데 아무 일도 안 하는 게 제일 나쁘다. 레벨이 생기면 글자와 콜백만 채우면 되고
배치는 그대로다.

스탯 막대의 "가득" 기준(체력 200 / 스태미나 200 / 공격력 40)은 성장 상한이 없어서 임시로
둔 눈금이다. 숫자를 막대 옆에 그대로 적으므로 이 값이 조금 어긋나도 정보가 틀리지는 않는다.

## 3. 커진 바가 창을 밀어냈다

바를 키우자마자 **코어 창이 퀵슬롯을 덮었다.** 창고 탭에서 퀵슬롯으로 끌어다 놓으려면
둘 다 보여야 하는데, 창이 슬롯 위에 얹히면서 그 조작이 통째로 막혔다(실제로 드래그가
실패하는 걸 확인했다).

두 가지를 고쳤다.

- **창은 하단 바가 예약한 높이를 침범할 수 없다.** 생성 시점에 창 높이를
  `화면 높이 − 하단 바 예약분`으로 자른다. 안쪽 내용은 잘린 높이에서 다시 계산되므로
  구역들이 알아서 줄어든다(§PanelBuilder.height).
- **창 위치도 그 공간의 가운데**로 잡는다(`Modal.recenter`). 화면 크기가 바뀔 때도 다시
  부른다 — 예전엔 생성 시점에 한 번만 놓아서, 창을 열어 둔 채 창 크기를 바꾸면 화면 밖으로
  밀려났다.

예약 높이는 `QuickSlotBar.BOTTOM_BAR_RESERVED` **한 곳**에서만 정의한다. 처음엔 창 높이
계산과 창 위치 계산이 각자 값을 만들었는데, 아래 여백(28px)을 한쪽만 빼먹어서 창이 막대를
12px 덮었다.

## 4. 검증

헤드리스 크롬으로 확인했다.

- 하단 바 렌더(직업 버튼 + 4칸 + 막대 둘), 캐릭터 창 렌더
- **창고 → 퀵슬롯 드래그가 다시 동작**(창이 바를 덮지 않게 된 뒤)
- 탄약 표시가 스태미나 막대 오른쪽 위에 자리 잡음
- 콘솔 오류 없음, shared 487 + server 31 테스트 통과

## 5. 남은 것

- 레벨·SP·스킬은 미착수(자리만 잡아 둠)
- 창 크기 자르기는 **생성 시점에만** 적용된다. 창을 열어 둔 채 화면을 크게 줄이면 위치는
  따라오지만 크기는 그대로다.
- 캐릭터 창의 초상화는 정면 대기 프레임 한 장이다. 직업별 포즈나 애니메이션은 후속.
