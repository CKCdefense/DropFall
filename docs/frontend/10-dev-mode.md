# 개발 모드 — 개발자 콘솔과 테스트 모드

모든 아이템·무기를 실제로 손에 들고 확인하려면 정상 진행(캐고 → 모으고 → 만들고 → 사고)을
전부 거쳐야 한다. 스프라이트가 손에 어떻게 붙는지, 소모품 효과가 도는지만 보려는 것뿐일
때는 그 과정이 전부 방해다. 개발 모드는 그 앞단을 건너뛰게 해준다.

## 켜는 방법

| 곳 | 조건 |
|---|---|
| 클라이언트 UI | `pnpm dev`(Vite 개발 서버) 이거나 URL에 `?dev=1` |
| 로컬 모드(`?local=1`) | 항상 켜짐 — 혼자 도는 시뮬레이션이라 망칠 남의 판이 없다 |
| 멀티플레이 서버 | `NODE_ENV !== production` **이고** `DROPFALL_DEV=1` 일 때만 |

```bash
DROPFALL_DEV=1 pnpm dev:server   # 서버에서 개발 커맨드를 받아준다
```

클라이언트에서 UI가 보이는 것과 서버가 실제로 실행해 주는 것은 **별개**다. 개발 플래그가
없는 서버는 `dev` 메시지를 조용히 무시한다(응답도 없다) — 존재를 알려줄 이유가 없다.

## 조작

| 키 | 하는 일 |
|---|---|
| `` ` `` | 개발자 콘솔 열기/닫기 |
| `F9` | 테스트 모드 — 아이템 도감 |
| `[TEST] WAVE 5` 버튼 | 보스 웨이브로 점프(로컬 모드 전용, 기존 기능) |

콘솔이 열려 있는 동안에는 Phaser 키보드가 꺼진다 — 안 그러면 명령을 타이핑하는 사이에
캐릭터가 걸어다니고 퀵슬롯이 바뀐다. 클릭도 공격으로 새지 않게 막는다.

### 콘솔 입력

- `Tab` — 명령 이름 자동완성(첫 낱말만. 아이템 id까지 하면 후보가 수십 개라 오히려 방해다)
- `↑` `↓` — 이전 명령 다시 꺼내기
- 앞의 `/`는 있어도 되고 없어도 된다. 대소문자도 가리지 않는다.

## 커맨드

`help`로 언제든 목록을 볼 수 있다(목록은 명령표에서 자동 생성되니 여기 표와 항상 일치한다).

| 명령 | 하는 일 |
|---|---|
| `give <아이템\|all> [개수]` | 인벤토리에 넣는다. 4칸을 넘긴 몫은 창고로 간다 |
| `store <아이템\|all> [개수]` | 코어 창고에 넣는다 |
| `drop <아이템> [개수]` | 발밑에 떨어뜨린다(줍기·바닥 렌더 확인용) |
| `clear [inv\|store\|all]` | 비운다(기본 `inv`) |
| `money <금액>` / `energy <양>` / `tier <단계>` | 팀 자금 / 공유 에너지 / 코어 티어 |
| `wave <번호>` | 해당 웨이브의 밤을 즉시 시작 |
| `day` | 몬스터를 치우고 낮으로 되돌린다(상점도 새로 뽑힌다) |
| `spawn <종류> [마리]` | 몬스터 소환. 코어에서 떨어뜨려 놓는다 |
| `killall` | 필드의 몬스터를 전부 지운다(보상 없음) |
| `heal` / `corehp <값>` | 내 체력 / 코어 체력 |
| `shop` | 상점 진열을 다시 뽑는다(등급 로테이션 확인용) |
| `list <items\|weapons\|consumables\|recipes\|monsters\|shop>` | id 목록 |

아이템은 **한글 이름으로도 찾는다** — `give 소총`이 `give rifle`과 같다. id를 외우고 있지
않으면 매번 목록을 뒤져야 해서 쓸모가 없다.

## 테스트 모드 패널(F9)

아이템을 종류별 탭(무기·도구 / 소모품 / 재료)으로 그림과 함께 보여준다. 칸을 누르면 바로
손에 들고, `Shift`를 누른 채 누르면 10개를 준다. 페이지 표시(`1/2 ▶`)를 누르면 다음 장이다.

콘솔의 `give`와 같은 일을 하지만 입구가 다르다 — id를 알고 있으면 콘솔이 빠르고, 뭐가
있는지 훑어보려면 그림이 있는 이쪽이 빠르다.

## 구조

```
shared/sim/devCommands.ts   명령 파싱 + 명령표 (규칙은 여기 한 곳에만)
shared/sim/world.ts         World.runDevCommand → DevWorldAccess 구현 제공
server/rooms/GameRoom.ts    dev 메시지 수신(DEV_MODE일 때만) → devResult 응답
client/ui/DevConsole.ts     DOM 오버레이 콘솔
client/ui/DevItemModal.ts   아이템 도감(F9)
```

명령 **해석은 클라이언트에서 하지 않는다.** 문자열을 그대로 넘기고 결과만 찍는다 — 규칙이
shared에 있어야 로컬 모드와 멀티플레이가 같은 결과를 낸다. 콘솔과 도감도 같은 커맨드로
내려간다.

`DevWorldAccess`는 World의 private 필드를 커맨드 모듈에 통째로 열지 않으려고 둔 통로다.
필요한 동작만 함수로 골라 넘기므로, World가 치트 때문에 부풀지 않고 명령표만 따로 테스트할
수 있다(`shared/tests/devCommands.test.ts`).

### 주의 — 낮 전환은 정상 경로와 같은 함수를 쓴다

`day` 커맨드는 `World.onDayBegan()`을 부른다. 웨이브를 정상적으로 클리어했을 때와 **같은
함수**다. 둘이 갈라지면 "커맨드로 넘긴 낮"에서만 상점이 안 바뀌거나 쓰러진 팀원이 안
일어나는 식의 차이가 생긴다.
