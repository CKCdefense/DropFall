# DropFall 게임 기획서

## 1. 개요

| 항목 | 내용 |
|---|---|
| 게임명 | DropFall |
| 장르 | 생존 / 디펜스 |
| 태그 | 멀티, 협동, 탑다운(3/4 시점 아트) |
| 플랫폼 | 웹 브라우저 (데스크톱 우선) |
| 인원 | 2~4인 협동 (1인 플레이 가능하도록 밸런스 스케일링) |
| 1회 플레이 시간 | 15~25분 (데모 기준) |

**한 줄 요약**
> 낮에는 자원을 모아 거점을 짓고, 밤에는 몰려오는 몬스터로부터 중앙 코어를 지키는 협동 생존 디펜스.

**컨셉 근거**
"떨어진다(Drop)"는 이름대로, 플레이어는 미지의 행성에 불시착한 생존자다. 중앙 코어는 구조 신호를
보내는 장치이며, 이것이 파괴되면 구조는 없다. N번째 밤을 버티면 구조선이 도착한다.

---

## 2. 승패 조건

- **승리**: 데모 기준 **5 웨이브**(정식 10 웨이브) 생존
- **패배**: 아래 중 하나
  - 중앙 코어 HP 0
  - 플레이어 전원 다운 상태 (다운 후 일정 시간 내 팀원이 부활시키지 못하면 사망)

> 전멸 즉시 패배는 협동 게임에서 체감이 나쁘다. **다운 → 부활** 시스템을 넣어
> "구하러 가는" 협동 순간을 만든다. 부활은 의사 직업이 더 빠르다.

## 3. 코어 게임 루프 (낮 / 밤 사이클)

```
[ 낮 90초 ] 자원 수집 · 건축 · 상점 · 성장   →   [ 밤 60~120초 ] 웨이브 방어   →   정산 → 다음 낮
```

웨이브가 올라갈수록 밤이 길어지고 낮은 짧아진다.

### 3.1 낮 컨텐츠 (준비 페이즈)

플레이어를 **거점 밖으로 내보내는 것**이 낮의 설계 목표다. 안에만 있으면 할 게 없어야 한다.

| 활동 | 내용 |
|---|---|
| 자원 채집 | 거점 밖 필드의 나무·풀(리젠), 광물·반도체(희소, 맵 외곽) |
| 건축 | 벽·울타리·포탑 설치, 파괴된 시설 수리 |
| 상점 | 코어 상점에서 무기·소모품 구매, 거점 영역 확장 |
| 성장 | 레벨업 스킬 포인트 분배, 테크 트리 해금 |
| 정찰 | 다음 웨이브 스폰 지점 미리 확인 (UI에 방향 표시) |

**긴장감 장치**: 희소 자원일수록 맵 외곽 = 코어에서 멀다. 밤이 시작되면 필드에 몬스터가
스폰되므로, "한 번 더 캐고 돌아갈까"의 리스크 판단이 낮의 핵심 재미다.
낮 종료 15초 전 경고 UI + 사운드.

### 3.2 밤 컨텐츠 (방어 페이즈)

- 맵 가장자리 스폰 포인트 2~4곳에서 몬스터가 코어를 향해 진격
- 스폰 포인트는 웨이브마다 달라지고, 낮 동안 UI로 예고된다 → **방어선 배치 전략**이 생김
- 웨이브 클리어 시 전원 소량 회복 + 정산 화면(획득 자원, 처치 수, 기여도)

### 3.3 플레이 텀 문제

낮에 할 일이 없으면 지루하고, 밤에 할 일이 없으면 방치 게임이 된다.

- 낮: 채집 → 건축 → 상점의 **동선이 겹치지 않게** 배치 (자원은 밖, 상점은 코어)
- 밤: 벽 뒤에서 사격만 하면 이기는 구조를 금지. 다음 장치로 개입을 강제한다.
  - 벽 수리는 밤에도 가능 (정비공이 유리)
  - 특정 몬스터(돌진형)는 벽을 우회하거나 넘어옴
  - 밤에도 드랍된 에너지 광물을 직접 주우러 나가야 함 (자동 수급 X)

| `Space` | 회피 구르기 *(TBD: 밸런스상 뺄 수도 있음)* |

## 5. 직업

각 직업은 **패시브 1 + 액티브 스킬 1(F키)** 로 최소 구성한다. 확장은 MVP 이후.

| 직업 | id | 패시브 | 액티브(F) | 역할 |
|---|---|---|---|---|
| **병사** | `soldier` | 총기 데미지 +15%, 재장전 속도 +20% | **집중 사격** (일정 시간 연사속도 상승) | 딜링, 돌파 대응 |
| **탐색꾼** | `searchman` | 이동속도 +15%, 채집 속도 2배 | **정찰** (일정 시간 시야 확장) | 자원 수급, 정찰 |
| **의무병** | `medic` | 부활 속도 2배, 자신 자연회복 | **치유 오라** (범위 내 아군 회복) | 생존력, 라인 유지 |
| **엔지니어** | `engineer` | 건축 비용 -20%, 수리 속도 2배 | **자동 포탑 설치** (지속시간/쿨다운 있음) | 방어선 구축, 밤 유지보수 |

> **id는 캐릭터 스프라이트 파일명과 같다** (`assets/sprites/characters/{id}.aseprite`).
> 정의는 [shared/protocol/lobby.ts](../packages/shared/src/protocol/lobby.ts) 한 곳에 있다.

**현재 상태**: 대기실에서 선택하고 인게임 스프라이트가 직업별로 바뀌는 것까지 동작한다.
**패시브/액티브는 아직 게임플레이에 반영되지 않는다** — 전투가 구체화될 때 붙인다.

**밸런스 원칙**: 어떤 직업도 단독으로 웨이브를 못 넘긴다. 엔지니어만 3명이면 화력이 부족하고,
병사만 3명이면 벽이 무너진다.

> **직업 중복은 아직 막지 않는다.** 네 명이 모두 병사를 고를 수 있다. 위 원칙과 충돌할 수
> 있어 플레이테스트 후 제한 여부를 정한다.

## 6. 성장

### 6.1 개인 성장 (레벨업)
- 몬스터 처치 시 경험치 드랍 → 주워서 획득 (파티 공유 X, 직접 획득)
- 레벨업 시 스킬 포인트 1 → 간단한 3갈래 트리
  - **생존**: 최대 HP, 방어력, 이동속도
  - **전투**: 데미지, 연사속도, 치명타
  - **유틸**: 채집 속도, 건축 비용, 인벤토리 칸
- 데모 기준 최대 레벨 10 전후

### 6.2 거점 성장 (팀 공유)
- **코어 레벨업**: 희소 자원 투입 → 코어 HP 증가, 거점 영역(건축 가능 범위) 확장, 상점 상위 품목 해금
- **테크 트리**: 반도체 등으로 해금. 무기 티어, 포탑 종류, 벽 상위 등급
- 코어 강화 vs 개인 무기 구매의 **자원 배분 갈등**이 협동 전략의 핵심

### 6.3 자원

| 자원 | 획득처 | 용도 |
|---|---|---|
| 목재 / 섬유 | 필드 오브젝트 (리젠) | 울타리, 벽, 기본 건축 |
| 광물 | 맵 외곽 바위 (희소) | 상위 벽, 포탑, 무기 제작 |
| 반도체 | 특수 지형 / 엘리트 드랍 | 테크 트리 해금 |
| 에너지 결정 | 몬스터 드랍 | 상점 화폐, 코어 강화 |
| 경험치 | 몬스터 드랍 | 개인 레벨 |

## 7. 아이템

### 7.1 방어 설비

| 이름 | 내구도 | 투사체 통과 | 특징 |
|---|---|---|---|
| 울타리 | 낮음 | **O** | 싸다. 뒤에서 사격 가능. 몬스터 이동 차단 |
| 벽 | 높음 | X | 비싸다. 시야·투사체 차단 |
| 문 | 중간 | X | `E`로 개폐. 아군 통로 |
| 자동 포탑 | 중간 | - | 정비공 스킬 / 상점. 탄약 소모 |
| 스파이크 | - | O | 밟는 적에게 지속 데미지 |

> **핵심 설계**: 울타리/벽의 차이는 "이동 차단"과 "투사체 차단"을 **분리된 두 속성**으로
> 다루기 때문에 성립한다. 기술 문서의 그리드 레이어 설계와 직결된다.

### 7.2 무기

| 분류 | 무기 | 특징 |
|---|---|---|
| 근접 | 몽둥이 | 시작 무기. 넉백, 탄약 불필요 |
| 근접 | 도끼 | 채집 속도 보너스 겸용 |
| 원거리 | 새총 | 초반 원거리. 돌맹이 소모(저렴) |
| 원거리 | 권총 | 표준. 중간 연사, 정확도 높음 |
| 원거리 | 기관총 | 고연사, 낮은 정확도, 탄약 소모 큼 |
| 원거리 | 산탄총 | 근거리 고데미지, 돌진형 대응 |

**탄약 설계**: 탄약은 상점 구매 또는 제작. 무한이면 밤이 지루해지고, 너무 빡빡하면
스트레스다. → 근접 무기는 항상 유효하도록 유지 (탄 떨어져도 싸울 수 있음)

### 7.3 소모품

| 이름 | 효과 |
|---|---|
| 붕대 / 약품 | 즉시 or 지속 회복 |
| 음식 | 최대 HP 일시 증가, 이동속도 버프 |
| 수류탄 | 범위 폭발 |
| 수리 키트 | 건축물 즉시 수리 |

- 폰트: 픽셀 폰트 (한글 지원 필수 — *TBD: 갈무리체 / Neo둥근모 라이선스 확인*)

1. 로비 (방 생성/입장, 직업 선택, 준비)
2. 인게임 HUD
3. 건축 모드 (그리드 오버레이 + 배치 프리뷰 + 자원 비용 표시)

5. 인벤토리 / 스탯
6. 웨이브 정산, 승리/패배

## 10. 밸런싱 원칙

1. **모든 수치는 JSON**. 코드 하드코딩 금지. 밸런싱은 빌드 없이 가능해야 한다.
2. **인원 스케일링**: 몬스터 수 = 기본값 × (0.6 + 0.4 × 인원수). 1인 플레이도 가능해야 한다.
3. 첫 2웨이브는 **무조건 이기게** 설계. 튜토리얼 역할.
4. 웨이브 3~4에서 처음으로 벽이 뚫려야 한다. "위기감"이 없으면 성장 보상이 무의미하다.
5. 자원 획득량은 항상 **살짝 부족하게**. 전부 살 수 있으면 선택의 재미가 없다.
