## 0. 총평

로드맵 W1~W5 범위(P0 전부)는 이미 훨씬 넘어섰다. **P2로 분류돼 "과감히 포기" 대상이었던
보스조차 이미 구현**돼 있고(심지어 웨이브 2~5마다 보스가 나옴 — 기획서는 웨이브 5 1회만
가정), 자원 게이지·레벨업·AI 컴패니언·LLM 페르소나 대화 같은 로드맵에 없던 기능까지
들어갔다. **"완성도"는 걱정할 단계가 아니고, 지금 리스크는 "심사위원이 실제로 접속했을 때
안전하게 끝까지 보여줄 수 있는가"** 쪽이다.

## 1. 데모 출시 전 반드시 필요 (Release-blocking)

### 1.1 배포 체크리스트가 전부 미완료
[07-deployment.md §7](07-deployment.md#7-배포-체크리스트-tech-spec-97과-동일)의 6개 항목이
**전부 미체크 상태**다:
- [ ] 외부 네트워크(모바일 핫스팟 등)에서 Pages URL 접속 → 서버 연결
- [ ] 3인 동시 접속 20분 이상 유지
- [ ] 서버 재부팅 후 자동 기동 + Funnel 유지 확인
- [ ] 로비 장시간 대기 → 연결 유지
- [ ] 콘솔에 mixed content/404 경고 없음
- [ ] 더미 커밋으로 두 CI 워크플로가 실제로 초록불인지 확인

배포 인프라 자체는 만들어져 있고(§1~6), 실제로 한 번 사고(Funnel이 `--bg` 없이 떠 있다가
꺼짐, 2026-08-08)도 겪고 고친 기록이 있다 — **즉 "배포는 됐지만 체크리스트로 마지막
확인은 안 했다"**. 데모 당일 접속 실패가 제일 치명적인 실패 유형이므로 최우선.

### 1.2 재접속(`allowReconnection`) 미구현
`packages/server/src`에 `allowReconnection` 관련 코드가 **전혀 없다**(grep 0건).
[02-tech-spec.md §4.4](02-tech-spec.md)가 "공모전 시연 중 사고 대비로 **필수 구현**"이라고
못박아 둔 항목인데 아직 없다 — 심사 중 와이파이가 잠깐 끊기면 그 플레이어는 그냥
탈락하고 재입장할 방법이 없다.

### 1.3 직업 패시브/액티브(F키) 미구현
`jobs.json` 자체 주석: `"스킬·특성은 아직 없다(추후 작업)"`. [01-game-design.md §5](01-game-design.md)도
"**현재 상태**: 대기실 선택 + 스프라이트만 바뀜, 패시브/액티브는 게임플레이에 반영 안 됨"이라고
명시하고 있다. 지금은 직업이 기초 스탯(체력/공격력/스태미나)만 다르고, **F키 자체가 아무
동작도 안 한다.** "직업 협동"이 게임의 핵심 셀링포인트인데 그 부분이 비어 있다.

### 1.4 튜토리얼/조작 안내 없음
`tutorial`/`온보딩` 관련 코드/UI가 0건. 로드맵 W7 항목("튜토리얼/조작 안내")인데 착수
안 됨. 심사위원은 처음 보는 사람이라 WASD/좌클릭/우클릭/E/B 같은 조작을 게임 안에서
알려줄 방법이 지금 전혀 없다 — 로비 화면이나 첫 접속 시 안내 오버레이 하나가 데모
체감에 큰 영향을 준다.

## 2. 있으면 데모가 훨씬 좋아짐 (권장, 필수는 아님)

### 2.1 사운드가 파일만 있고 코드에 0% 연결
`git log`상 "음악 추가" 커밋이 있었지만, 실제로는:
- 파일이 `assets/audio/{bgm,sfx}/`(프로젝트 컨벤션)가 아니라 **저장소 루트의 `sounds/`**에
  들어갔다(`sounds/boss/`, `sounds/night/`, `sounds/peace/`)
- `packages/client/src`에 `sound`/`audio`/`Audio` 문자열이 **0건** — 로드/재생 코드가
  아예 없다
- 저장소 루트에 내용 없는 `pnpm` 파일(0바이트)이 같이 딸려 들어감 — 실수로 생긴 파일로
  보임, 삭제 대상

무음 데모는 임팩트가 크게 떨어진다. 최소 낮/밤 BGM 전환만이라도 붙이면 체감이 크게 다르다.

### 2.2 방어 설비 5종 중 3종 미구현
[01-game-design.md §7.1](01-game-design.md)의 방어 설비(울타리/벽/**문**/**자동 포탑**/**스파이크**)
중 `buildings.json`엔 울타리·벽 계열(`fence`/`wall`/`stone_*`/`iron_*`)만 있다. **문, 포탑,
스파이크는 데이터 자체가 없다.** 포탑이 없으면 엔지니어 직업의 액티브 스킬("자동 포탑
설치")도 만들 게 없다 — 1.3번과 맞물린 문제.

### 2.3 정찰(다음 웨이브 스폰 지점 예고) 없음
[01-game-design.md §3.1](01-game-design.md)의 "스폰 지점은 웨이브마다 달라지고, 낮 동안
UI로 예고된다 → 방어선 배치 전략"이 설계 의도인데, 관련 UI가 없다(grep 0건). 지금은
밤이 시작돼야 어디서 오는지 알 수 있어서 "미리 방어선을 짠다"는 전략성이 빠져 있다.

### 2.4 낮 종료 경고 없음
"낮 종료 15초 전 경고 UI + 사운드"([01-game-design.md §3.1](01-game-design.md))도 미구현.
사운드는 2.1과 겹치는 문제고, UI만이라도 먼저 붙일 수 있다.

## 3. 데모엔 굳이 필요 없음 (그대로 둬도 됨)

- **테크 트리** — 로드맵이 처음부터 P2(포기 대상)로 분류. 코어 강화/레벨업으로 성장
  루프는 이미 대체됨
- **AOI(관심 영역) 최적화** — 3~4인 룸 규모에선 안 급함, PATCH_RATE 50Hz 검증도 이미
  통과했다([backend/61](backend/61-work-report-session-handoff-verification.md))
- **회피 구르기** — 기획서에도 `TBD: 뺄 수도 있음`으로 표기된 항목
- **4번째 직업** — 로드맵은 3종 + "4번째는 아이디어만"이었는데 **이미 4종(병사/탐색꾼/
  의무병/엔지니어) 전부 구현됨** — 오히려 초과 달성

## 4. 추천 순서 (시간이 없다면)

1. **배포 체크리스트 실제로 통과시키기** (§1.1) — 데모 당일 접속 자체가 안 되면 나머지는 의미 없음
2. **재접속 구현** (§1.2) — 이미 있는 Colyseus 기능 붙이는 정도라 상대적으로 비용이 낮음
3. **튜토리얼/조작 안내 최소 버전** (§1.4) — 로비 화면에 조작키 안내 이미지 한 장이라도
4. **직업 스킬 최소 구현** (§1.3) — 4개 전부 완벽하지 않아도, 패시브 수치 적용 + 액티브
   버튼이 뭔가는 하게만 해도 셀링포인트가 살아난다
5. 시간이 남으면 사운드(§2.1) → 포탑/문(§2.2) → 정찰 UI(§2.3) → 낮 경고(§2.4) 순
