# 몬스터 스프라이트 — 저장소에 커밋하지 않는다

> **이 디렉터리는 비어 있는 게 정상이다.** `.gitignore`가 이 안의 그림 파일을 전부
> 막고 있다. 몬스터 아틀라스 산출물(`public/assets/atlas/monsters.*`)도 마찬가지다.

## 왜

여기 쓰는 에셋 팩의 라이센스가 이렇다.

| | |
|---|---|
| ✅ 허용 | 개인·상업 게임 프로젝트에 사용 / 프로젝트에 맞게 **수정** |
| ❌ 금지 | **재배포·재판매·재업로드 (수정본 포함)** / AI 학습 / NFT |

`CKCdefense/DropFall`은 **공개 저장소**다. 커밋하면 전 세계가 파일을 내려받을 수
있고 — 그게 곧 재업로드다. 그리고 금지 조항이 "**수정본 포함**"이라 **Lua로 색만
바꾼 변형본도 똑같이 못 올린다.** 원본이 아니니 괜찮겠지, 가 통하지 않는다.

한번 커밋되면 나중에 지워도 **git 히스토리에 영구히 남는다**(히스토리 재작성 + 강제
푸시 + 팀원 전원 재클론이 아니면 안 지워진다). 그래서 애초에 안 들어가게 막았다.

**게임에 쓰는 것 자체는 허용이다.** 배포한 웹 빌드가 브라우저에 `monsters.png`를
내려주는 건 "게임에 사용"이지 "에셋 재배포"가 아니다. 막아야 하는 건 저장소뿐이다.

## 왜 아틀라스를 따로 뽑나

원본만 무시하면 소용이 없다. 예전엔 몬스터가 `game` 아틀라스에 함께 묶였는데,
**아틀라스 PNG에는 픽셀이 그대로 박힌다.** `.aseprite`를 무시해도 `game.png`를 통해
그림이 그대로 올라간다.

그래서 몬스터만 `monsters` 아틀라스로 떼어냈다.

```
game.png       캐릭터·아이템·건축·이펙트   → 커밋함 (팀원은 클론만 하면 됨)
monsters.png   몬스터                      → 커밋 안 함 (각자 빌드)
```

`game.png`는 그대로 커밋되므로, **에셋 작업을 안 하는 팀원도 여전히 클론 → 실행이
된다.** 몬스터 그림만 없는 상태가 되고 그때는 기존 도형 플레이스홀더로 그려진다.

## 받는 법

1. 팀 공유 채널에서 에셋 팩을 받는다 → **공유 위치: 비공개 저장소
   `CKCdefense/dropfall-assets`** (없으면 배포 담당에게 초대를 요청한다).
   배포도 같은 저장소를 쓴다 — GitHub Pages 빌드가 여기서 완성된 아틀라스를
   주입한다(.github/workflows/deploy-pages.yml의 ASSETS_SSH_KEY 주석 참고).
2. 압축을 풀어 이 디렉터리(`assets/sprites/monsters/`)에 넣는다
3. `pnpm build:atlas`

명명 규칙은 다른 스프라이트와 같다 — `mob_` 접두사, 태그 하나 이상
([assets/README.md](../../README.md) 참고).

## 커스터마이즈 (색 변형 등)

색 변형·형태 수정은 라이센스가 **허용**하는 범위다. 다만 결과물은 여전히 못 올린다.
그래서 **결과물이 아니라 변환 과정을 커밋한다.**

```
assets/sprites/monsters/mob_slime.aseprite   원본  → 커밋 안 함 (라이센스 에셋)
assets/_generators/monsters_recolor.lua       레시피 → 커밋함 (우리가 쓴 코드)
assets/sprites/monsters/mob_slime_red.aseprite 결과 → 커밋 안 함 (수정본도 금지)
```

Lua 스크립트에는 픽셀이 아니라 "어떤 색을 어떤 색으로 바꾼다"는 규칙만 들어간다.
저장소에는 우리가 쓴 코드만 남고, 팀원은 원본 + 스크립트로 같은 결과를 재현한다.
변형 내역이 코드 리뷰에 남는다는 이점도 있다.

**스크립트에 원본 팔레트를 통째로 하드코딩하지 않는다** — 그건 사실상 에셋 일부를
올리는 것이다. 색 하나하나가 아니라 색상환 회전·명도 조정 같은 **연산**으로 쓴다.

## 공모전 제출

제출물에 소스 코드가 포함된다면 이 디렉터리는 비어 있는 채로 나간다. 실행 빌드에
그림이 들어가는 건 라이센스상 문제없지만, 심사에서 에셋 출처를 물을 수 있으니
**팩 이름과 라이센스 원문을 프로젝트 크레딧에 적어 둔다** (Credit is appreciated).
